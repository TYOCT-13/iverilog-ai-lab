# 项目实施计划

## 阶段一：确定性验证闭环

- 建立 Python 包、命令行入口与结构化结果模型。
- 建立模十计数器和交通灯状态机的正确设计、缺陷版本与规范。
- 使用本机 Icarus Verilog 12.0 和 vvp 执行真实仿真。
- 生成机器可读结果和 Markdown/HTML 报告。

退出条件：正确设计通过，至少两个可编译缺陷设计被相应场景稳定检出，测试可重复运行。

## 阶段二：AI 测试规划

- 定义严格的测试计划 JSON Schema。
- 提供确定性 mock provider，保证离线可复现。
- 提供通过环境变量配置的 OpenAI-compatible provider。
- 拒绝或重试不合法输出，禁止模型直接执行命令。

退出条件：离线测试覆盖合法、非法和修复后输出，AI 层可替换且不侵入仿真核心。

## 阶段三：基准与评测

- 扩展 ALU 与序列检测器。
- 建立功能缺陷基准（当前已扩展到 70 个，覆盖 12 个案例）。
- 在同等测试预算下比较固定、随机和 AI 规划策略。
- 记录检出率、误报率、计划合法率和首次发现时间。

## 阶段四：演示与参赛材料

- 完成 Streamlit 单页演示。
- 补齐 GitHub Actions 模板、许可证清单和复现文档。
- 形成技术报告、演示脚本和 3 至 5 分钟视频素材。

## 统一质量门槛

新增或修改的 Verilog 需记录 `compile`、`ast`、`readability`、`comment`、`naming`、`profile`、`testbench`、`toolchain` 八项状态。任何功能结论必须来自真实工具输出，不能由模型自评替代。
