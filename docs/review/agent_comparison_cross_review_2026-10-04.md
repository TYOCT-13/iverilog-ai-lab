## 必须披露的限制与改进建议

### A. 同周期上限不等于同观察能力

`testbench.py` 仅在多周期向量最后一拍进行该向量的预期输出检查。随机基线每拍一条向量，API 可以生成少量长向量，因此相同周期数可能对应明显不同的检查次数，短暂差异可能只被密集采样捕捉。固定/随机填满预算，API 可以提前停止或因计划超预算而不执行。

当前 pilot 应写“相同累计激励周期上限”，并分别展示实际周期、向量数、检查数和停止原因；不要写成所有策略采样强度完全一致。后续正式评测可以另设统一采样方式的实验，但不能在看完本轮成绩后只替换某一策略来拼接结果。

### B. 反馈内容不支持失败定位修复的主张

Agent 发现反例即停止，所以能够进入下一次请求的实际观察通常是此前没有差异的摘要与检查数量。它不会在此实验中依据已确认反例继续定位或修复。无反馈组虽将 observation 置空，但“还能继续运行”仍隐含此前未触发停止；协议已明确保留同一失败停止规则。

本轮比较的是“显式仿真摘要是否影响后续输入选择”，不能描述成“失败日志指导修复”，也不能将这种消融解释为完全消除了所有环境信息。

### C. 冻结完整性需要执行后验收

脚本在结束时生成 `changed_inputs_at_finish`，但不会自动把非空变化标记转成无效总体结论。初审发现协议 Markdown 未包含在初始哈希中，主代理已在冻结提交 `0de10a0` 修正。结束后仍必须确认变化列表为空。若代码/输入在执行期间变化，该轮应作废或单列为受影响的开发记录，不能作有效能力结论。

### D. 失败运行的成本是已观测下界

样本的 `search_cycles` 由成功完成参考审核并追加至汇总的 rounds 相加。若真实目标仿真已执行、但随后的参考回放抛异常，或异常发生在产物汇总之前，该行的汇总周期可能少于实际发生的执行；相应 Agent 轨迹和仿真目录可能保留更多记录。参考审核耗时也包含在总样本 elapsed 中，未单独提供搜索耗时。

因此不能把错误样本的零汇总周期解释为确实没运行，也不能据此计算准确的全部成本或首次检出时间。当前检出率分母仍保留失败，未发现因此虚增有效检出。正式成本分析需交叉核对轨迹和目录，无法恢复的部分明确记未知。

补查中断与费用：真实 Provider 在传输前递增 `request_count`，样本 finally 从该计数取请求数并仅向总数累加一次；Agent 和外层最终保存会在正常异常展开及 `KeyboardInterrupt` 时执行。中断发生时当前样本可能仍标 `not_started`，但不从分母删除；应额外核对已有 rounds 和磁盘轨迹，不能把该标签解读成绝对没有发生执行。进程被强杀或机器掉电不保证 finally 执行，最后一个未保存请求的计数和用量可能不可恢复。usage 缺失保持未知，`cost_currency=null` 也符合未取得服务商账单的事实；不能将它转成免费或零成本。

### E. 正确基线与参考误报统计需要细分

`reference_false_alarm_samples` 汇总所有带该状态的策略样本，既可能来自独立正确基线任务，也可能来自变体任务的参考回放。它不是直接的“正确设计误报率”。报告应区分独立正确基线假警与回放判据否决，并给各自分母；不能将汇总次数除以正确基线任务数。

### F. 试验规模和顺序限制

默认每种策略每样本仅一次，远程模型没有可保证确定性的配对随机种子；策略按固定顺序执行。服务状态波动、输出随机性及短规格均可能影响结果。全局 cap 若低于理论请求数，会让靠后的样本更易缺预算；默认 84 次覆盖理论上限，但仍应核对实际请求数与所有状态。当前结果最多是 pilot，不支持统计显著性或行业泛化结论。
