## 5 个未执行任务的真实原因

逐条读取了轨迹所引用、尺寸和 SHA 匹配的 `untrusted_decisions/decision-001.json`；它们仅作为未受信任的模型原始输出复核，没有送入执行器或参考判据。4 条格式拒绝均为新增了 schema 不接受的顶层字段，**不是额外 `type` 字段**。

| sample | 模块 / 缺陷 / seed | 原始原因 | 原始提案周期 / 硬上限 | 最终状态 |
| --- | --- | --- | ---: | --- |
| 015 | FIFO / `fifo_bug_full_off_by_one` / 0 | 额外 `vector_count`、`total_cycles` | 3/16 | `policy_error` |
| 051 | UART / `uart_bug_msb_first` / 0 | 额外 `cycle_sum` | 40/48 | `policy_error` |
| 055 | UART / `uart_bug_msb_first` / 1 | 额外 `cycles_total` | 45/48 | `policy_error` |
| 071 | UART / `uart_bug_busy_never_clears` / 2 | schema 接受，但提出 85 周期，超过硬上限 | 85/48 | `cycle_budget` |
| 099 | SPI / `spi_bug_done_missing` / 0 | 额外 `cycles` | 17/20 | `policy_error` |

以上每条均花费 1 次请求、0 个执行周期，没有自动重试。36 次请求全部有用量；32 个 decision 通过 schema，其中 1 个随后因超预算未执行，另有 4 个 decision 被拒绝。因此是 31 次 API 目标执行，不是 32 或 36 次。

5 条均是缺陷任务，保留在 24 的分母和 36 请求、78,934 tokens 的用量中。它们没有有效执行证据，所以整轮 `eligible_for_frozen_comparison=false`，而 `frozen_input_snapshot_verified=true`。这是有效执行完整性与原字节快照两个不同判断，不能把后者写成整轮严格资格通过。

## 发现的提示冲突与公平性边界

执行器和实际首轮 state 的硬限制确为 FIFO16、UART48、SPI20、握手8；`max_rounds=1`、`max_requests=1`，所有策略用同一模块 cap。UART、SPI 的短 cap 能容纳一帧及空闲恢复，不能说这些预算本身使完整事务不可能。

但 runner 原样载入的模块规格仍含旧预算：

| 规格位置 | 仍出现在本轮首请求的文字 | 本轮硬上限 |
| --- | --- | ---: |
| [FIFO 第 35 行](../../spec/sync_fifo_spec.md#L35) | 已验证累计激励预算 160 周期 | 16 |
| [UART 第 33 行](../../spec/uart_tx_spec.md#L33) | 累计激励周期上限 512，多轮共享 | 48 |
| [SPI 第 32 行](../../spec/spi_master_spec.md#L32) | 本轮累计激励周期上限 384，多轮共享 | 20 |
| [握手第 32 行](../../spec/handshake_stage_spec.md#L32) | 本轮多轮共享累计激励预算 160 周期 | 8 |

这些旧文字与同一首轮 state 的 `remaining_rounds=1`、`remaining_stimulus_cycles`、`max_new_cycles` 并存。硬 cap 没有失效；这是模型输入的语义冲突。UART sample-071 确实提出了 85 周期，但单次结果不能证明旧文字导致超预算，也不能用此解释抹去输于随机的结果。下一版应把通用电路语义与本次资源预算分开，清理旧的“本轮/多轮”预算陈述，再另行预注册；不得追改本轮原件或补测后替换本轮失败。

相同 cap 也不等于所有实际资源相同：三基线通过截断或末态保持补齐至上限，single 的短提案不补齐，超上限则拒绝。方案中“按相同上限归一化”只能理解为共同上限，不能描述为四组实际刺激周期完全相同。固定模板还可含计入刺激预算的手动复位；所有组仍另外执行合同自动初始复位。实际周期、参考审核、墙钟耗时、请求和用量应分别披露。

## 结论边界

此方案是在看过旧开发结果后新设短预算的探索性试验，目标仍是默认参数的已知开发模块。它与上一轮充裕预算的 8/8 结果是不同实验，不能混合择优，也不能将本次首轮规划成绩解释成后续失败反馈或覆盖反馈的因果收益。

保留的结论是：**在本轮实现、提示和短预算条件下，API 首轮规划主指标为 15/24，均匀随机为 16/24，尚未显示超过随机；固定与协议随机均为 21/24。** 这不是普遍显著性、复杂 SoC 泛化或真人体验结论。提示预算冲突和执行拒绝是下一版可修复的问题，修复后的成绩需要新证据。
