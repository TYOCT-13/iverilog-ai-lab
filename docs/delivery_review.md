## 三、做过的尝试（含被推翻的结论）

### 3.1 实验路线

| 轮次 | 口径 | 结果 | 学到的 |
|---|---|---|---|
| 首测 09-10 | 1 模型 / 11 案例 / 256 次仿真 | 在线 45/54 检出（83.3%），固定 35/54 | AI 路径可行，但发现**参考误报 25/40** |
| 修复口径 | — | 参考误报归零 | 根因：AI 猜错期望值同时被算作"误报"与"检出"；改为参考模型复算并覆盖 AI 数字 |
| 双模型 09-11 | 2 模型 / 12 案例 / 62 缺陷 / 6 次重复 | 两模型检出**完全相同**（58/62），pro 的 AI 期望值准确率低 11 个百分点 | 判决与"模型算数准不准"解耦；更强模型 ≠ 更高检出 |
| 双模型 09-12 | 2 模型 / 13 案例 / 67 缺陷 / **10 次重复** | flash **65/67**（97.0%）、pro **64/67**（95.5%），参考误报均 0 | 提高重复次数后"检出完全相同"不再成立；两模型漏检**几乎不重叠**（并集 66/67） |

完整记录：`docs/experiment/`（4 份，含逐条未检出原因与 token 明细）。

### 3.2 被推翻或修正过的结论（这部分是可信度的一部分）

| 曾经的结论 | 为什么被推翻 | 处理 |
|---|---|---|
| "80 个缺陷全部检出" | 复核发现两个变体**代码逐字节相同**，属重复登记 | 删除重复项，换成根因独立的新缺陷；新增"重复缺陷检测"门禁 |
| token 消耗 1,428,261 / 1,391,722 | 按**行**累加 usage，而一次请求的计划被同案例所有变体复用（放大 6–13 倍） | 按请求去重后为 236,028 / 231,036；两篇实验文档加"口径更正"并保留原数字 |
| 对比表"重复次数 5" | 用"行数 ÷ 请求数"算，而行数是变体数 | 改为按 seed 去重计数；补回归用例 |
| 报告配图上的 14/14、78/78 | 脚本找错了文件名，**永远读不到**真结果，回退到硬编码旧值 | 按真实产物名读取；读不到就渲染"—（未运行）"，不编造 |
| "离线路径可以完整跑通" | 实测离线计划**端口全空**（合约没从提示词解析出来）+ 设计名丢失，仿真"通过"却什么都没测 | 修复解析链路；新增**离线 AI 路径矩阵**（15/15）作为常态化门禁 |
| 参考模型有独立诊断实现 | 那份 150 行是实现副本且位于 `return` 之后（死代码） | 删除死副本，新增"未可达代码与重复定义"检查 |
| 网页"读取模型列表"可用 | 两个按钮写在 `return` 之后，**从未渲染过** | 移到设置面板并接上下游；新增 UI 冒烟测试（用 Streamlit `AppTest` 真渲染） |

### 3.3 工程上踩过的坑（已固化为文档或门禁）

- **Icarus 语义**：非阻塞赋值读旧值——参考模型对齐中 3 个错误都源于此（`docs/reference_model_alignment.md`）。
- **Yosys (WASM)**：`-s 脚本` 不可读、`-q` 吞掉 `stat -json`、ABC 阶段静默中断 → 判据改为"有没有拿到统计"（`docs/layered_evidence.md`）。
- **覆盖率指标**：只报"信号动没动"没有区分力（弱激励也 100%），加入**取值覆盖**后才能区分 38% vs 6%（`docs/coverage.md`）。
- **提示词上下文**：把 36 KB 约定 JSON 整篇塞进上下文会撞上 20000 字符上限，且只有真实模型路径会暴露（离线 mock 不经过该路径）。
- **编码卫生**：PowerShell 写文件引入 UTF-8 BOM 会被 `ast.parse` 拒绝；中文注释被写坏成成串问号不会报错 → 两者都进了 CI 门禁。

## 五、需要审核/拍板的点

1. **技术报告的详略**：现在草稿把"证据分层""噪声校准""口径更正"都写进去了。评委可能更喜欢
   直给的结论。**要不要压缩"过程性内容"、把关键数字前置？**
2. **2 个未检出缺陷怎么写**：我主张照实写（相位/观测点问题，且手写边界 TB 能检出）。
   如果担心被认为"检出率不是 100%"，可以强调"两模型并集 66/67"。
3. **视频主线**：候选是（a）一次完整流程演示，（b）"AI 提出假设、开源工具裁决"的对比实验，
   （c）缺陷检出矩阵实跑。**3–5 分钟只能讲一条主线，选哪条？**
4. **是否把试用记录做成正式佐证**：需要至少 1–2 位外部同学按 `docs/trial/` 跑一遍并回填
   反馈表。这属于"可验证效果"的加分项，但要花 40 分钟人力。
5. **上游 Issue 是否提交**：提交后需要跟进回复，且要如实记录"已提交/已回复"。
   如果时间紧，可以只作为"准备好的材料"提交而不实际发帖。
6. **定价表**：`data/model_pricing.json` 里 DeepSeek 价格仍为 `null`（未核验）。**要不要查官方
   定价页填上并标注核验日期？** 填了才能在报告里给金额。
7. **参赛方向的表述**：目前主投（二）AI 开发工具与开源协作，兼（三）。**是否需要按某一方向
   重写摘要与亮点顺序？**
