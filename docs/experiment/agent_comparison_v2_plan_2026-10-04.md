# Agent v2 评测计划（执行前冻结）

本计划是开发集上的重复实验，不是真人试用、独立人工审核或独立留出评估。不预设模型优于基线。旧 `e9b7b8a` 的60行结果、首次中断目录和已有报告保持原样，不与v2合并成绩。

## 入口与范围

`scripts/run_agent_comparison.py --profile v2` 显式启用新版。默认仍为legacy：五种旧策略、一次重复、原有budget_for预算及common_cases短说明；没有新版配置时legacy仍能运行。v2配置缺失或非法则失败，不静默回退。

v2默认四模块、每类清单前两个缺陷及正确基线、三次重复、七策略，共252行。四个API策略的每样本请求上限为1/3/3/3，理论360次。实际请求由执行者明确指定总cap；默认cap=0，保留全部API任务为未执行，不能称为完成能力实验。运行顺序固定，cap低于理论上限可能使后面的任务更易缺预算，须如实披露。

固定模板的重复使用同一份输入，不是三份独立人工设计。seed对本地随机基线可复现；对远程模型只是重复编号，不保证服务商随机性可复现。

新增策略：

- `protocol_random`：只读取合约、规格配置与种子，生成UART/SPI完整发送事务，忙期间重新发起尝试，FIFO空满及读写边界，握手反压与稳定载荷；不读变体标签、触发描述或目标源码。
- `feedback_no_coverage`：继续真实仿真与普通观察反馈，只从模型可见观察中去掉功能覆盖信息；完整覆盖记录仍落盘。
- `feedback`：普通反馈与功能覆盖均可见；`no_feedback`隐藏全部观察；`single`仅一次建议。反馈组与无覆盖组的API提案是独立随机调用，不是假定同一远程随机种子的配对模型运行。

## 规格、预算和采样

`spec/agent_protocols.json`是新版规格路径、timing与累计周期预算的单一来源；四个模块分别160/512/384/160周期。模型读取spec_path全文，不再只有一行简介。规格描述现有RTL行为，包括FIFO同拍读写的计数规则和SPI实际输出时序，不将其冒称标准通用IP。

v2还同步修复FIFO正确基线与参考模型的同拍接受读写计数：两者均接受时净变化为0，空满边界仍依据边沿前状态；历史缺陷文件不改。因此新旧版本同时涉及规格、基线、判据、预算和观察采样的变化，不能把成绩差异单独归因于功能覆盖或提示词。正式运行前由执行者核对修复与协议对齐测试。

v2的两个FIFO目标由`benchmarks/agent_v2/mutation_manifest.json`替换：从修正基线各施加一次原有mutation operator，并校验基线快照和变体SHA。其余六个目标仍来自原清单，缺陷总分母为8。这些都是开发集人工变体新版本，不是独立留出。旧FIFO变体继承旧计数行为，继续保留历史目录，不能混入新版本声称为单点对照。

TestPlan上限200向量。v2均匀随机因此最多生成200个输入段，将总周期尽量均匀分配到各段；UART/SPI可能每段2–3周期。它不是旧profile的逐周期随机，结果必须显示实际向量数、检查数和采样密度。协议随机完整事务不足以放入剩余预算时，只补idle，不截断成“已完成整帧”。固定模板仍复用现有模板，末态延长至预算。各策略都没有通过修改周期表来追求更高结果。

协议随机UART在每位结束检查，SPI在每个忙沿检查，避免只采样整帧结束的idle。达到200向量容量、无法容纳下一完整事务时，剩余周期也只补idle；因此SPI可能没有持续发满全部周期。该向量容量与实际采样行为同时披露，不将空闲周期解释为新增事务覆盖。

所有策略使用真实观察快照。功能覆盖是规格命名事件的执行记录，不是RTL代码覆盖率，不等同正确性判据。参考审核单独回放，不把参考源码、标签、审核结果传给搜索模型。

v2各策略统一将工具输出捕获上限设为2,000,000字符，容纳长计划逐周期快照；截断或缺失快照不当作完整覆盖。legacy仍使用200,000字符默认值。

Agent每轮重新执行旧计划，全部周期计入搜索预算；参考审核周期单列，自动复位开销不包含。周期上限相同不表示实际消耗、断言数、token或总耗时相同。

## 记录与统计

请求前保存预注册与运行设置，冻结源代码、完整规格、配置、协议随机实现、覆盖实现、协议文档和system-prompt/profile指纹。变更检测在开始和结束执行；改变冻结输入的结果不得作为严格同版本能力结论。

`--thinking-mode enabled|disabled`是明确的服务商扩展设置，默认不指定（JSON null）；不指定仅表示遵循服务商默认，绝不解释为关闭思考。模式与含义在请求前写入`run_settings.json`并由结果中的SHA绑定，属于本次比较配置；相同prompt/profile哈希但模式不同也不能混作同一条件。正式v2由执行者显式选择`--thinking-mode disabled`，provider_factory测试入口保持原调用契约。没有以放宽动作schema处理截断。

显式thinking模式仅支持Chat Completions；Responses同时传显式模式会在读取密钥、创建输出目录和发请求前拒绝。默认null在两个协议下均不注入thinking字段。

`598e6dc`故障预跑目录`.iverilog-ai/agent-comparison-v2-live-20261004`已人工中止，全部登记行和已有请求记录保留，仅作开发记录。后续使用新目录，实际授权cap扣除已发生请求后由执行者决定；不补造未运行数据。

逐轮保存计划、实际检查数、记录数、向量数、检查密度、已用/剩余周期、参考审核尝试/完成周期及耗时、模型usage和错误。首反例周期使用实际失败记录；累计搜索消耗为前轮全部周期加当前失败的零基周期加一。没有周期的失败保持null。物理失败发生时的墙钟时间不可从日志精确恢复，`first_detection_elapsed_seconds`保持null，另记结果可获得时间，不能误称硬件失败瞬间。

每个重复单独固定缺陷分母，错误、截断、无判据和未完成均保留；报告逐重复检出率、均值和范围。独立缺陷并集另列，不能代替单轮平均。正确基线假警和变体参考审核否决分列。参考异常或无检查不算有效检出。

汇总拒绝预注册不可变字段冲突，依共享判定函数及实际round/reference证据重新认定检出。原始pipeline、计划、合约、TB、结果和工具日志均保存SHA，字节或观察摘要不一致、原件缺失时标记`evidence_unknown`且不可作为完整冻结比较。汇总的`result_available_elapsed_seconds`来自首个有效检出轮的实际结果可获得时间；物理失败墙钟时间仍为null。此校验用于发现证据不一致，不构成第三方签名或防伪认证。

严格的`eligible_for_frozen_comparison`要求每行都有可核验的仿真证据。因此真实API拒绝、截断但没有执行round的行，也会使整轮资格为false。资格为false不等于删除该行：所有分母、已知usage和错误继续保留，可以描述有限实际结果，但不能宣称整轮均满足冻结可核比较。不能为获得理想值而重新挑选样本或拼接运行。

`eligible_for_frozen_comparison`严格要求每个注册样本都有可核验仿真与参考原件。真实API拒绝或截断导致没有执行轮时，该资格也为false；仍保留全部注册分母和失败终态，可以描述这次有限运行，不能删去失败、缩小分母或挑选重跑片段来取得资格。

中断正常展开时恢复轨迹用量，保留未开始行；强杀/掉电可能遗失在途请求更新，未知用量不补成零。费用无服务商账单时为null。输出目录已存在即拒绝，重跑须新目录，不能挑选最好片段拼成一轮。

## 命令

```powershell
python -X utf8 scripts/run_agent_comparison.py --profile v2
python -X utf8 scripts/run_agent_comparison.py --profile v2 --execute --strategies fixed random protocol_random --output-dir .iverilog-ai/agent-comparison-v2-offline
```

真实API由执行负责人配置实际endpoint/model、密钥文件和明确请求cap后启动；本计划不读取或包含凭据。没有自动重试、自动额度追加或服务商切换。

运行后另存汇总，输入原件不修改：

```powershell
python -X utf8 scripts/summarize_agent_comparison.py .iverilog-ai/agent-comparison-v2/results.json --output .iverilog-ai/agent-comparison-v2-summary.json
```
