# v7 信用 / 仲裁子组的完整只读诊断

范围是全部108任务：六策略各18任务，其中Agent54任务（36缺陷＋18正确控制）。以下只分析既有冻结v7轨迹，不调用API、不执行DUT，不构成新模型成绩、因果估计或独立人审。完整逐任务与逐请求表分别为 rows.json 和 decision_audit.json，summary.json绑定输入SHA。

确认的共同信息缺口：反馈组18轨迹共47请求，28次已有前次observation。全部28次只有运行/检查/失败摘要与unsupported场景覆盖，没有真实端口采样。相反证据是42个已执行反馈episode的observed_samples全部完整；另外single16、no_feedback36个实际episode也全部完整。发生功能失败时failure_samples确实可以给出少数实际输出值，所以不能声称反馈完全没有实测数据。缺口是未检出情况下缺少可继续规划的完整端口过程信息。

信用计数：反馈九任务共119刺激拍，八拍用于显式复位；九任务中仅四个到过正确规格的0边界后再次消耗，三个在7边界再次归还。其六个缺陷任务只检出两个。三个目标B的反馈都没有在正确规格0状态下消耗；分别是先增加到上限后未充分消耗、短序列重复后提前停止、跨两次独立复位分散消耗。不能把累计消耗次数直接当成同一episode的连续可达路径。一个请求reason写after replay，但执行状态明确fresh/不延续/不重放；实际执行均遵守独立复位。

仲裁：反馈九任务共121刺激拍，其中16拍用于显式复位，26个episode全部独立自动复位。全部九任务都出现多请求，但只有六个出现多请求且advance=0；没有一项连续保持同一多请求组合和advance=0，也没有连续保持同一多请求组合和advance=1。四个位的单请求选择、一次竞争输入或笼统one-hot检查不足以全面观察正确规格定义的跨拍优先级保持、推进和环回。该行为描述来源正确规格，不将目标标签或见证写入新提示词。

预算和早停也真实影响探索：反馈信用组四个cycle_budget、一个repeated_action、一个格式错误；仲裁组六个round_budget、一个model_stopped。反馈总计240刺激拍，比两类随机基线的288拍少，并有24拍显式复位；single还存在两个未执行信用任务的末请求预算拒绝。不能把所有失败都归于端口摘要，也不能通过扩大额度或回写旧成绩掩盖这些限制。

可泛化修复路径：给模型返回经过stdout和输入SHA绑定、值无关选点、有界的真实端口采样，保留X/Z与省略数量；场景覆盖仍如实unsupported。规划依据正确规格计算每个新episode从自动复位状态到目标行为所需连续拍数，避免不必要的显式复位，把保持/推进及完整协议时序与剩余周期一起考虑。方案不得注入变体名称、私有witness、旧分数或固定答案。验证这种改动后仍需新的事前登记实验，当前诊断不证明检出改善。
