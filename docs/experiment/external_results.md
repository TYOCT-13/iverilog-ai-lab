# 外部模块验证结果（P0-D，第 1 个模块）

对象：`alexforencich/verilog-uart` 的 `uart_rx`（MIT，Verilog-2001）。
这是**第一次在非内置、非本项目编写的 RTL 上**跑完整的"合约 → 激励 → Icarus → 行为对比"链。

复现命令（需要先抓取上游文件）：

```powershell

python scripts/check_external_module.py         # 跑规格测试台 + verify-diff 逐变体比对
```

## 2. 人工合约（显式确认，不是猜的）

```json
{"module": "uart_rx", "parameters": {"DATA_WIDTH": 8},
 "clock": {"signal": "clk", "period_ns": 10, "edge": "posedge"},
 "reset": {"signal": "rst", "active_level": 1, "synchronous": true, "assert_cycles": 3}}
```

**关键点：`rst` 是高有效、同步复位**（源码是 `always @(posedge clk) if (rst)`）。
按端口名猜会猜成"低有效"——这正是本轮 A 修掉的那类静默猜测：猜错的话，
测试台会把 DUT 一直摁在复位里，缺陷版本看起来"和基线完全一致"。

## 3. 测试设计：两个真实踩到的坑

两个坑都是**先跑出错结果、再改对**的，写在这里因为它们决定了检出的上限：

1. **测试字节不能是位序回文。** 第一版用 `0xA5`（`1010_0101`）——正反读一样，
   于是"数据位序写反"的变体在行为上与基线**完全相同**，`verify-diff` 老实地说"一致"。
   换成 `0x96`（`1001_0110`）后立刻检出。
2. **激励没覆盖到的地方检不出。** 第一版的计划只发正常帧，于是"不检查停止位"的变体
   也判"一致"；在计划里补一帧**停止位为 0** 的帧之后，它变成"不同"。
   这不是工具变强了，是激励变全了——正好是本项目想说明的那件事。

## 4. 结果（8 个输入，全部离线、本机 Icarus）

| 输入 | 手写规格测试台 | `verify-diff` | 应当是 |
|---|---|---|---|
| 基线（上游原样） | **全过**（11 项检查） | `identical` | 一致 ✅ |
| 等价改写（decrement/比较换成等价写法） | **全过** | `identical` | 一致 ✅ |
| 变体：复位极性反转 | 6 项失败 | `different` | 不同 ✅ |
| 变体：数据位序写反 | 1 项失败 | `different` | 不同 ✅ |
| 变体：帧长多一位 | 5 项失败 | `different` | 不同 ✅ |
| 变体：不检查停止位 | 2 项失败 | `different` | 不同 ✅ |
| 变体：tvalid 不会被 tready 清掉 | 1 项失败 | `different` | 不同 ✅ |
| 编不过的实现 | 编译失败 | `inconclusive` | 未取得可比证据 ✅ |

- **5/5 功能变体全部被 `verify-diff` 判"不同"**；等价改写判"一致"（没有误报）；
  编译失败判 `inconclusive` 而**不是**"不同"——路线图要求的三类区分都成立。
- 规格测试台是**基线正确性的依据**（手写、只依据 UART 规范，不看 DUT 内部实现）：
  基线 11 项全过，等价改写也全过，5 个变体分别挂在不同检查上。
- 证据：`.iverilog-ai/external/uart_rx_check/evidence.json`（含合约、测试字节、每个输入的
  规格测试结果与 `verify-diff` 状态）。

- 没有独立微型测试之外的规格文档：`uart_rx` 的"规格"目前是 UART 帧格式的通行语义 +
