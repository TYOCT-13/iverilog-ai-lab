# 外部模块验证结果（P0-D，三模块历史记录）

对象：`alexforencich/verilog-uart` 的 `uart_rx`（MIT，Verilog-2001）。
这是**第一次在非内置、非本项目编写的 RTL 上**跑完整的"合约 → 激励 → Icarus → 行为对比"链。

本记录从 `uart_rx` 开始，随后在 §5、§7 追加 `uart_tx` 与 `priority_encoder`；当前范围以 §8 的三个模块汇总为准。此处仅修正文档范围说明，没有新增实验或改写历史结果。

历史本机运行入口（需已经备齐冻结输入，不能作为全新环境的一键复现命令）：

```powershell
python scripts/check_external_module.py         # 仅在可执行副本中运行，会重写固定目录产物
```

当前 `fetch_external_modules.py` 抓取的是 `common_cells`，不能补齐这里的 UART / priority_encoder 输入；检查脚本另有本机工具路径依赖。请先按 `docs/review/independent_review_guide.md` 取得冻结输入并确认环境，保留原始证据后在副本重放。

## 2. 人工合约（显式确认，不是猜的）

```json
{"module": "uart_rx", "parameters": {"DATA_WIDTH": 8},
 "clock": {"signal": "clk", "period_ns": 10, "edge": "posedge"},
 "reset": {"signal": "rst", "active_level": 1, "synchronous": true, "assert_cycles": 3}}
```

**关键点：`rst` 是高有效、同步复位**（源码是 `always @(posedge clk) if (rst)`）。
按端口名猜会猜成"低有效"——这正是本轮 A 修掉的那类静默猜测：猜错的话，
测试台会把 DUT 一直摁在复位里，缺陷版本看起来"和基线完全一致"。

## 3. 测试设计：两个真实踩到的坑

两个坑都是**先跑出错结果、再改对**的，写在这里因为它们决定了检出的上限：

1. **测试字节不能是位序回文。** 第一版用 `0xA5`（`1010_0101`）——正反读一样，
   于是"数据位序写反"的变体在行为上与基线**完全相同**，`verify-diff` 老实地说"一致"。
   换成 `0x96`（`1001_0110`）后立刻检出。
2. **激励没覆盖到的地方检不出。** 第一版的计划只发正常帧，于是"不检查停止位"的变体
   也判"一致"；在计划里补一帧**停止位为 0** 的帧之后，它变成"不同"。
   这不是工具变强了，是激励变全了——正好是本项目想说明的那件事。

## 4. 结果（8 个输入，全部离线、本机 Icarus）

| 输入 | 手写规格测试台 | `verify-diff` | 应当是 |
|---|---|---|---|
| 基线（上游原样） | **全过**（11 项检查） | `identical` | 一致 ✅ |
| 等价改写（decrement/比较换成等价写法） | **全过** | `identical` | 一致 ✅ |
| 变体：复位极性反转 | 6 项失败 | `different` | 不同 ✅ |
| 变体：数据位序写反 | 1 项失败 | `different` | 不同 ✅ |
| 变体：帧长多一位 | 5 项失败 | `different` | 不同 ✅ |
| 变体：不检查停止位 | 2 项失败 | `different` | 不同 ✅ |
| 变体：tvalid 不会被 tready 清掉 | 1 项失败 | `different` | 不同 ✅ |
| 编不过的实现 | 编译失败 | `inconclusive` | 未取得可比证据 ✅ |

- **5/5 功能变体全部被 `verify-diff` 判"不同"**；等价改写判"一致"（没有误报）；
  编译失败判 `inconclusive` 而**不是**"不同"——路线图要求的三类区分都成立。
- 规格测试台是**基线正确性的依据**（手写、只依据 UART 规范，不看 DUT 内部实现）：
  基线 11 项全过，等价改写也全过，5 个变体分别挂在不同检查上。
- 证据：`.iverilog-ai/external/uart_rx_check/evidence.json`（含合约、测试字节、每个输入的
  规格测试结果与 `verify-diff` 状态）。

## 5. 第 2 个模块：同一个仓库的 `uart_tx`（发送侧，环回验证）

来源与许可同 §1（同仓库 `rtl/uart_tx.v`，3077 B，sha256 `e9559ddebf124f8f…`）。

规格测试台做成**环回**：`uart_tx → uart_rx`，收到的字节必须等于发出的。好处是不用人工数拍
去采样串行位——位序、停止位、位周期任何一处错了环回都会失败。这正好是第一版 rx 测试台
手工采样踩坑的反面教材。

| 输入 | 规格测试台（环回） | `verify-diff` | 应当是 |
|---|---|---|---|
| 基线 | **全过（10 项检查）** | `identical` | 一致 ✅ |
| 等价改写 | 全过 | `identical` | 一致 ✅ |
| 变体：复位极性反转 | 5 项失败 | `different` | 不同 ✅ |
| 变体：位周期少一拍 | **全过** | `different` | 不同 ✅（见下） |
| 变体：停止位发成 0 | 4 项失败 | `different` | 不同 ✅ |
| 变体：busy 不清 | **全过** | `different` | 不同 ✅（见下） |
| 变体：发出的字节差一 | 4 项失败 | `different` | 不同 ✅ |
| 编不过的实现 | 编译失败 | `inconclusive` | 未取得可比证据 ✅ |

**两个方法各有盲区，正好互补**（这是本轮最有用的一条观察）：

- **环回测试台漏掉的两个**：
  - *位周期少一拍*：接收侧是 8 倍过采样，±1 拍的波特率误差它容忍得了，所以环回照样通；
    但 `verify-diff` 拿 `txd` 波形与基线逐拍比，立刻看出不同。
  - *busy 不清*：我的测试台只检查了"发送中 busy 为 1"，没检查"发完 busy 归 0"；
    `verify-diff` 把 `busy` 当输出端口比对，直接抓到。
- **`verify-diff` 漏掉而规格测试台抓到的**：没有——本轮 5/5 都被 `verify-diff` 判了"不同"。

## 6. 本轮新增的三条测试设计教训（都是先做错、后改对）

1. **测试字节不能是位序回文**（§3 第 1 条）：`0xA5` 正反读一样，"位序写反"的变体在行为上
   与基线完全相同。改成 `0x96` 后立刻检出。
2. **激励没覆盖到就检不出**（§3 第 2 条）：只发正常帧时"不检查停止位"的变体判"一致"；
   补一帧停止位为 0 的帧之后变成"不同"。
3. **测试台不要与 DUT 抢同一个时钟边沿**：`@(posedge clk); tvalid = 1'b0;` 会在同一个时间步里
   与 DUT 的时钟块竞争，谁先执行不确定——第一版因此"DUT 根本没收到数据"，
   表现为 `busy` 检查误报失败（`bit_cnt=0`、`prescale_reg=0`，一看就知道是没接受）。
   改成"拉高 `tvalid` → 等两个边沿 → 再撤"。

另外发现：我原本想造的"tready 不再拉高"变体，查源码后确认它与原实现**语义等价**
（发送期间 ready 本来就是 0，帧尾又会置 1），所以 `verify-diff` 判"一致"是**正确**的，
不是漏检。已换成真正的数据通路变体（字节差一）。

## 7. 第 3 个模块：`priority_encoder`（**参数化输入**这一类）

来源：`alexforencich/verilog-axi` 的 `rtl/priority_encoder.v`（MIT，Verilog-2001，92 行）。

**来源说明（必须写明）**：它属于**开发集**——本项目的静态约定规则就是从 `verilog-axi` 抽取的
（见 `external_modules.md` §1）。所以它是"别人写的 RTL"，但**不是**未见过的保留集；
它在本项目里的用途是**工具预检样例**，不能当外部保留集证据。

为什么选它：前两个模块都是"8 位数据 + 时钟 + 复位 + 握手"，缺"参数化"这一类。它是**纯组合逻辑**
（没有时钟也没有复位），行为由 `WIDTH` 与 `LSB_HIGH_PRIORITY` 两个参数决定，于是一格覆盖三件事：
参数化位宽、两种参数取值的对照、以及**无时钟设计**的合约路径（合约里不写 clock/reset，
而不是猜一个出来）。规格测试台里**同时实例化两个参数取值**，直接检验"参数化"本身。

| 输入 | 规格测试台 | `verify-diff` |
|---|---|---|
| 基线 | **全过（28 项检查）** | `identical` |
| 等价改写 | 全过 | `identical` |
| 变体：对内优先级取反 | 7 项失败 | `different` |
| 变体：valid 只看奇数位 | 8 项失败 | `different` |
| 变体：编码差一 | 16 项失败 | `different` |
| 变体：独热输出变成全 1 | 16 项失败 | `different` |
| 变体：valid 恒为 1 | 1 项失败 | `different` |
| 编不过的实现 | 编译失败 | `inconclusive` |

写这个测试台时也踩了一个坑：`input expected_msb`（漏写位宽）会被当成 1 位，
`expected_msb[1:0]` 于是报 `can not select part of scalar`。**测试台的编译错误同样要当回事**，
否则会得到"这一行没有结论"而不是"实现有问题"。

## 8. 三个模块的合计结果

| 模块 | 类型 | 功能变体 | `verify-diff` 判"不同" | 规格测试台抓到 | 等价改写 | 编不过 |
|---|---|---|---:|---:|---|---|
| `uart_rx` | 握手 + 有限状态控制 | 5 | **5/5** | 5/5 | 判"一致" | `inconclusive` |
| `uart_tx` | 握手 + 有限状态控制 | 5 | **5/5** | 3/5 | 判"一致" | `inconclusive` |
| `priority_encoder` | **参数化输入**（纯组合） | 5 | **5/5** | 5/5 | 判"一致" | `inconclusive` |

**合计 15 个功能变体，`verify-diff` 判"不同" 15/15**；三个基线全部通过规格测试台；
三个等价改写全部判"一致"（无误报），三个编不过的输入全部判 `inconclusive`（未被误判为"不同"）。
