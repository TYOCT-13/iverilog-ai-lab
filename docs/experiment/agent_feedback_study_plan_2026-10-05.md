# Agent v8：有界端口反馈的完整对照事前方案

本方案在任何本批 API 请求之前冻结。使用已获授权的 DeepSeek Flash / 4.1f API；不加载本地模型权重。全部登记任务与所有失败请求共用一个输入加输出不超过 1,000,000 tokens 的账本，历史用量另存，不扣本批，不拆批继续失败样本。

## 为什么修订

v7 完整批次保留 432 项任务，反馈和无反馈均检出 37/48，信用/仲裁子组反馈 4/12、随机 8/12。30 个普通格式拒绝中 27 个涉及多余顶层字段，3 个涉及向量超过 12 个。信用/仲裁的后续反馈请求虽有实际逐拍采样工件，模型状态未包含端口采样，只有检查数、失败数及 unsupported 覆盖信息。

这些是工程缺口与描述性诊断，尚不能证明漏检的因果来源。本版只做通用修复：由实际校验模型生成决策层级约束，明确向量字段位置和连续输入分段；说明独立 episode 必须重新从复位出发规划完整路径；给模型提供有限的真实端口采样摘要。不开启特定缺陷提示，不加入私有见证、目标代码或历史成绩。

## 固定范围与公平性

- 保留 v7 的全部八模块、正确目标和每模块两个缺陷，三次重复、六策略，共 432 项；每策略 48 缺陷任务和 24 正确控制。16 个不同缺陷重复三次，不当作 48 个独立设计。
- 模块为 FIFO、UART、SPI、握手、信用控制、轮转仲裁、边沿检测和脉冲展宽。八类都已有 Agent 实测暴露。本轮不是新的留出；信用/仲裁和边沿/脉冲的历史分组仅作分层统计。v7 当时的模块集合留出报告保持不变。
- 六策略为 fixed、random、protocol_random、single、feedback、no_feedback。目标成员、规格、正确参考、基线算法、seed 顺序及分段均与 v7 相同；事前绑定旧登记并核对这些字节，禁止根据旧检出矩阵重选目标。
- FIFO 16、UART 48、SPI 20、握手 8、其余 16 个累计刺激周期。每提案最多 12 向量、累计接受最多 64；single 一次请求/一次实际回合，feedback/no_feedback 至多三次共享请求/三次实际回合，理论总上限 504 次。
- 格式与合法预算拒绝共用请求上限，拒绝不模拟、不裁剪、不占刺激或接受向量；传输错误、凭据/重复键/无法可靠检查的字符串等仍终止，不放宽 schema。
- 每实际 episode 独立复位，所有输出逐拍 after 检查，AI 不设置期望值。每次实际 episode 独立重放正确 RTL；复位和参考成本单列。
- 六策略均捕获同样的真实端口工件。feedback 可见已核验的有界端口摘要和已有功能覆盖；no_feedback 的 observation、plan_error、latest_decision_error 仍为 None。no_feedback 自有计划、剩余预算和执行器早停仍存在，不能称完全盲化。
- 摘要使用当前完整进程 stdout、采样 packet 摘要及 RTL/计划/合约/测试台来源绑定。最多 12 个确定性端点及等间隔样本，明确省略数；不按判据或失败挑样本，不补齐缺采样、不改 X/Z、不推断内部状态，不携带文件路径或预期值。失配、缺件和不充分采样返回空样本的固定错误码。
- 既有功能覆盖仍只认原来审计的四种接口配置；其他模块保持 unsupported。端口事实不冒充覆盖率或通过证明。外部 typed differential observer 的接口保持原样。

## 冻结与资源

执行前必须完成源码验证、只读事前代理复核及本地 Git 提交，工作树干净。登记当前全部源码、执行器依赖、规格、目标、正确参考、配置、方案和新专项测试的原字节 SHA，运行前后核对；旧字节登记及结果不改写。API 只收到正确规格、接口、当前输入计划、允许反馈和预算，不收到 RTL/私有标签/见证/旧结果。

API 使用 chat_completions、deepseek-flash、thinking disabled、非流式、单请求输出上限 4096、超时 60 秒、无自动传输重试、store=False。所有请求先保守预留输入加输出；未知用量不按零处理，实际账本原样保留。整个 432 项顺序走完；额度或状态错误使未请求项仍留在完整分母，不另批补齐。

修订包含结构提示、通用复位规划文案和端口反馈三项变化；历史差值仅描述，不能当作单因素因果效果。同一批 feedback/no_feedback 作为反馈消融，single 是一次请求辅助组。seed 只控制本地基线和顺序，不锁定服务端模型采样。

## 统计与交付

主指标为每策略检出缺陷任务 /48；分别给出三重复 /16、16 不同缺陷并集、三历史分组与模块矩阵。正确控制 /24 按策略区分已执行、失败、未执行和误报，不能把未执行写作通过。完整性资格依据全部执行与证据核验，不因检出率好而放宽。

辅助统计包含格式拒绝字段/位置、有界补提次数、原响应保留/blocked、实际回合、拒绝后真实执行与检出、首实际回合及后续回合检出、每任务请求/tokens/周期/用时、端口反馈完整与不充分计数。只有发生带剩余请求机会的真实预算拒绝且后续执行，才报告自然 API 预算恢复实例；脚本或 Icarus 机械回归与模型收益分开。

输出保存全部结果、轨迹、允许留存的失败原响应、每侧 plan/stdout/stderr/VCD、预算原账、登记快照和 ZIP/逐文件摘要，另行只读代理核对。不用最好一次代替全统计，不删除失败分母，不将代理核对记作真人试用或 H02。若效果没有提升，如实写出，后续只按新证据处理明确缺口。
