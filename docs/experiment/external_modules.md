# 外部模块验证：选型标准、开发集与保留集

本文件记录 P0-D（外部独立验证）的**选型依据与当前进度**。它是一份工作记录：
写到这里的每一条都注明了来源与核验时间；**没有核验的一律标"待核验"，不写成已适配**。

## 1. 为什么不能直接用仓库里已经有的上游代码

路线图要求"少量许可明确、**未参与调参**的模块"，并"明确区分开发集与保留集"。
查了一下现状，这条比想象的更要紧：

| 上游仓库 | 许可 | 用途 | 结论 |
|---|---|---|---|
| `alexforencich/verilog-axi` @`516bd5dadc` | MIT | **已用于抽取静态约定规则**（`data/opensource_conventions.json` 的 `sources[0]`） | **开发集**：规则是从它的码风里量出来的，不能再声称"未见" |
| `ZipCPU/wb2axip` @`2e8d3bc2d2` | GPL-3.0-or-later | 同上（`sources[1]`） | **开发集**；且 GPL 代码不适合进本仓库 |

两者的源码快照都在 `.iverilog-ai/upstream-cache/`（不进版本库）。约定抽取只保存了
**聚合统计与文件哈希**，没有保存上游源码——这一点是对的，继续保持。

**因此**：这两个仓库可以作为"工具开发与预检样例"，但**不能**作为 P0-D 的保留集；
在报告里引用它们时必须写明"开发集/已参与规则调参"。

## 2. 选型标准（先写下来，再挑，避免事后按结果挑模块）

1. **许可明确**：MIT / Apache-2.0 / Solderpad-0.51（可择 Apache-2.0）之类，仓库内有 LICENSE 文件。
2. **未参与过调参**：没有被本项目用来生成规则、提示词或基准。
3. **规模小、单时钟、端口明确**：能在 Icarus 下编译，且不需要厂商原语/加密 IP。
4. **类型互补**：覆盖参数化输入、握手/缓冲、有限状态控制等不同需求。
5. **可验证**：能写出独立微型测试或引用其自带测试，作为"可信基线正确性"的依据。

### 3.1 为什么 `common_cells` 没被选上（有证据的工具链限制）

本机 Icarus 是 **12.0 (devel) s20150603**，2015 年的快照，SystemVerilog 支持不完整：

| 文件 | 结果 |
|---|---|
| `src/cc_lzc.sv` | 补齐 include 后仍 `syntax error`（第 17 行） |
| `src/cc_fifo.sv` / `src/cc_rr_arb_tree.sv` | 需要 `common_cells/deprecated/registers.svh`，master 上已不存在该路径 |
| `src/cc_spill_register.sv` / `cc_shift_register.sv` / `cc_stream_fifo.sv` | `syntax error`（`parameter type` 等 SV 特性） |

另外仓库已把模块统一改名成 `cc_*`（`src/counter.sv` 之类的旧路径已 404），
所以任何按旧名字写死的抓取脚本都会失败——这也是本轮踩到的第一个坑。

**结论**：不是许可问题，是**工具链版本**问题。要接 `common_cells`，
要么升级 Icarus（>= 11 的较新版本对 SV 支持好得多），要么改用 Verilog-2001 的模块。
本轮选了后者（`verilog-uart`），并把这条限制如实写进报告，而不是声称"已适配"。

## 4. 每个模块要产出的材料（选定后按此执行）

- 上游 URL、**commit**、许可证、来源文件 **SHA-256**、修改边界与选择标准；
- **人工合约**（端口方向/位宽、时钟边沿、复位极性与同步性）——按本轮的规则，
  这些必须是显式确认的，不允许自动提取器猜；
- 可信基线 + 等价改写 + 约 5 个**独立审核过**的功能变体（目标 3 个模块共 15–20 个缺陷）；
- 每份实现都要有独立的微型测试/规格依据（"只与基线一致"不能替代规格验证）；
- 缺陷细节由复核人掌握，**模型提示词与规划规则不得读取**；
- 预检样例与正式保留变体**分开**；冻结后再改规则/提示词，原集合降级为开发集。

## 5. 命名口径

这些变体应称为"**基于真实外部模块的人工变异**"。除非确实对应上游历史上的修复，
否则**不得**称为"真实社区漏洞"或"历史 bug"。
