# Agent v5：采样、补测与执行证据

本轮继续使用服务商 API，不训练或运行本地模型权重。提示词为 v5；评测开关 `--profile v3` 是新实验配置名，与旧 Agent v3 提示词不是同一版本。

## 实际解决的问题

旧 Agent 容易把多拍输入当成一段等待。测试台确实执行了这些周期，但只在输入段末尾核对输出；UART 恢复空闲后，帧中间的位序错误就被漏掉。新模式按参考模型的每拍状态核对全部输出，原计划和输入段数保持不变，不重复套用段末期望。

`VerificationPipeline.run(..., reference_sampling="per_cycle")` 显式开启逐拍检查。库默认 `vector_end` 保留旧末态语义。逐拍支持已对齐的15个内置默认合约、沿后采样和确定的二进制输入；未支持的参数、相位或参考策略明确拒绝。自定义 RTL 的接口定义不能代替功能判据。

Agent 支持 `agent_plan_mode="independent"`：本轮新输入由真实测试台复位后执行，电路状态与输入电平不延续，历史仍保存在轨迹。网页默认选择独立运行；库默认 `append` 保留重放方式，并照实累计全部重放周期。模型状态中明确说明下一次复位、重放开销、可驱动端口和剩余周期。

合法 JSON 仍须通过接口及参考约束预检。非法提案保留请求与用量，不伪造仿真轮次；有剩余请求时允许再次提案。初始用户计划错误和已开始的仿真基础设施错误不静默改写。界面显示未执行提案，轨迹同时保存安全错误码、失败尝试和真实执行结果。

## 对照与审核

新实验所有固定、均匀随机、协议随机和 API 策略统一逐拍检查。四模块正确基线的零 API 代理复核中，每组检查密度相同：FIFO 480/160拍、UART 1024/512拍、SPI 1536/384拍、握手480/160拍，均无误报。只说明这些具体执行的对齐，不证明任意输入都正确。

功能场景仍以当前执行的实测采样为准，首拍不猜测输出前态，也不借用上一轮的采样。需要观察空闲到请求的转换时，新一轮输入应包含可测的空闲前导；自动复位不冒充一条已采集的前态记录。

请求前保存预注册清单、完整输入原字节、配置和提示词指纹；逐拍期望绑定原计划、合同、RTL、实际测试台及参考模型源码 SHA。汇总器还核对真实 stdout 的 RESULT、原执行结果和失败记录，不能只修改失败列表或采样标签提高检出数。失败任务始终留在登记分母。

独立代理审核记录见 [代码复核](../review/ic_v5_code_review_2026-10-05.md)。这是机器与代理检查，不替代真人试用或 H02 独立人工复核。

新在线实验按 [请求前计划](agent_comparison_v5_plan_2026-10-05.md) 单独保存。它同时改变提示词、采样和调度；新旧差异不能单独归因于模型或覆盖反馈，也不能把本节离线回放合并成新在线成绩。

## 使用

网页：选择内置案例，在“自动验证 Agent”中使用“每轮独立运行”和“逐拍检查输出”；在线配置仍使用私有 API 配置。累计周期、API 请求及轮数分别限制，达到任一限制即停止。选择重放时，已有输入也计入累计周期。

命令行先检查配置，不发请求：

```powershell
python -X utf8 scripts/run_verification_agent.py --case uart_tx --agent-plan-mode independent --reference-sampling per_cycle --thinking-mode disabled --dry-run
```

实际执行时追加 `--execute`，显式提供私有 API 配置和新的输出目录；不要把密钥写进命令、报告或 Git。轨迹候选导出只接受对应的当前提示词版本，旧 v4 不会由新提示词重建成 v5。导出不代表已经微调。
