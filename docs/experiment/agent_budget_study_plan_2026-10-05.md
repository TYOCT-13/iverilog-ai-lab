# Agent v7 预算补提完整对照：事前登记

本方案在本批第一次 API 请求前提交到本地 Git。源代码父版本为 `1566459b475a3ab07c95e5e8502982a9b7a9ad49`；执行时记录新的干净源码提交及所有实际输入字节。旧批次结果不修改。

## 要回答的问题

v6 中合法 JSON 仍可能提出超过剩余周期的计划，导致立即停止。本版允许这类尚未执行的提案在同一请求额度内补提。拒绝不运行 DUT、不消耗刺激周期、不占已接受向量，不裁剪提案或增加额度。错误只包含执行器产生的固定代码和整数，原响应与费用仍入账。格式补提与预算补提共享请求上限。重复已接受动作、重复 JSON 键、凭据回显等仍按原规则终止。

本批检验完整任务完成情况、预算补提的真实收益，以及相同资源下六种策略的检出表现。预算补提的脚本测试不作为付费 Agent 检出证据。

## 固定样本与分母

八个模块，每模块一个正确实现及两个缺陷，三次重复，六策略，合计 **432 任务**。每策略 **48 缺陷任务及 24 正确控制**；16 个不同缺陷的三次重复不视为48个独立设计。组别分别报告：

|组别|模块|每策略缺陷 / 正确任务|说明|
|---|---|---|---|
|development|FIFO、UART、SPI、握手级|24 / 12|原开发集，既往已用于 Agent 对照|
|prior_internal_holdout|信用计数器、轮转仲裁器|12 / 6|曾在 v6 下留出，本批已是既往 API 暴露模块|
|module_set_holdout|边沿检测器、脉冲展宽器|12 / 6|已有离线基准；此前受控 Agent 批次不含这两个模块|

前四模块继续使用此前已登记的两个缺陷，信用与仲裁继续使用原A/B/C；后两模块按既有基准 manifest 顺序取每类型前两个缺陷，在本批 API 前选择并保留全部。后两者不是 v7 冻结后新创作设计，也不是外部盲测。整个八模块集合不能称独立留出，后两模块仅作模块集合留出子组。所有目标、参考 RTL、契约、规格和私有见证字节均登记；API 仅收到正确功能规格、接口及受控状态，不接收 RTL、路径、变异标识、见证、旧结果或审核资料。

## 同批资源与流程

策略为 fixed / random / protocol_random / single / feedback / no_feedback。每任务累计刺激周期分别为 FIFO16、UART48、SPI20、握手8，其余16；每提案最多12向量、累计最多64接受向量。single 最多1请求，另两 Agent 最多3请求/3实际回合。理论上限504请求。不同错误补提共享这些上限，每次实际 episode 独立复位，所有输出逐拍 after 比较。刺激与参考审计周期分开报告，复位成本不计入刺激但单独统计。

全部432任务共享 **输入+输出不超过1,000,000 tokens** 的一个账本。历史消耗不扣入；未知费用保留并按请求保守预留。不拆批、不另给留出子组新额度。到达费用/请求边界后未执行任务仍在原分母中；不给失败任务单独重跑。输出上限4096，网络超时60秒，无自动传输重试，非流式，thinking=disabled，DeepSeek Flash / 用户指定4.1f API，不运行本地权重。

执行顺序为 seed、variant rank（正确控制优先）、module rank；策略顺序按三者之和轮转。模型服务随机数不能配对控制，seed 仅是重复编号/本地基准随机种子，不等于固定模型采样。

三种本地基准同样最多12个输入段。random 对每个业务输入独立均匀抽样，总周期按最多12段均分，禁止依据变异/检出重选抽样。旧四模块 fixed/protocol_random 改为公共协议事务的压缩段表示，保持完整逐拍检查；信用/仲裁沿用原12段内基准。后两模块使用正确规格基准。所有基准 expected 为空，输出预期由冻结参考模型产生。基准脚本不读目标、变异、见证或结果。

与旧 v6 批次相比，本版同时改变一般预算提示和旧四模块基准向量分段。因此历史数值只供背景，本批相同资源比较才是主要结论，不宣称单因素因果提升。功能覆盖仍使用已有分析器，对不支持模块保留 unknown，不增加定制提示。no_feedback 隐藏仿真观察、格式诊断和计划/预算错误；执行器成功早停及本身额度状态仍存在，不是完全盲化。

## 判定与原件

主指标为全部登记缺陷任务中的证据核验检出率；正确控制的误报单独列出。保留格式/预算拒绝、停止、超时、请求或费用耗尽、零 DUT 和部分执行失败，不用成功子集取代全分母。逐模块、逐重复、不同缺陷 union、第一/后续实际回合、接受与执行次数分别报告。至少一个任务没有有效真实执行证据时，严格完整比较 eligibility 为 false，不把脚本流程成功等同全面通过。

必须保存每次安全原响应、原文 SHA、schema/plan 状态、usage、失败阶段，以及所有实际与参考 pipeline/stdout/stderr/VCD/计划。安全规则禁止保存的凭据回显或重复键原文只保留相应安全字段/哈希，不从错误对象重造原文。公开完整原件 ZIP 和 manifest，并核对源码提交、快照与原始字节；Git 仅换行差异也须列明。

审核是另一子代理的只读机器复核，不能记为真人试用、外部独立审稿或 H02 人审。跨机复现、远程 Actions、真人、视频和费用账单的未完成状态保持真实。
