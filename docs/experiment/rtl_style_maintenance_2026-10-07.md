# 两模块 RTL 样式修复与公开双侧重放

2026-10-07，六份RTL的命名和组合逻辑风格问题已在[独立维护版本](../../benchmarks/rtl_style_maintenance_20261007/README.md)解决。严格静态门禁0错误、0警告；原版与维护版的真实双侧仿真在所测向量中全部一致。公开入口已实际完成一次完整运行，18份规格产物逐字节重建相同。

原2026-10-05实验的六源、12项风格问题、模型输出、统计和v3材料均原样保留。新源码会改变模型可能接收的文本，旧模型成绩不能自动外推到本维护版本。本次没有调用模型API。

## 改动与功能边界

事件累计器内部计数信号采用规范名称，输出显式保留原四位宽度。两个模块的控制条件按普通`case`拆开，保持复位分支、接口、寄存器和时钟延迟。没有新增流水寄存器，也没有用别名隐藏上游组合运算。

原六源r3记录的12项严格风格问题为3项命名和9项组合操作预算；新六源严格风格均通过。组合操作计数的改善是风格工具的度量，不是物理时序或功耗改善证据。

| 变体 | 保留的实际行为 | 公开正确规格判据失败数，原/新各侧相同 |
|---|---|---|
| event_accumulator A | 正确参考 | 0 |
| event_accumulator B | 忽略enable | 1 |
| event_accumulator C | clear仅在enable有效时生效 | 1 |
| valid_data_pipeline A | 正确参考 | 0 |
| valid_data_pipeline B | 输出valid取当前输入而非前次捕获状态 | 5 |
| valid_data_pipeline C | valid未被flush清除 | 1 |

B/C是检出用人工缺陷。其规格图解释缺陷行为，不能把门禁通过写成B/C功能正确。

## 实际验证与分母

| 验证 | 首次私有验证 | 公开版实际重放 | 解释 |
|---|---|---|---|
| 官方严格源码门禁 | 6源，0错误/0警告 | 6源，0错误/0警告 | compile/ast/readability/comment/naming/profile均passed；另外两项not_requested |
| 公开合同与正确判据 | 6对原/新，共12次DUT | 同组12次DUT | 171项输出值比较相同，判据结论及故意失败数相同 |
| 四态与边界 | 12对原/新，共24次DUT | 同组24次DUT | 4944项输出值比较相同；编译、运行exit均0 |
| 总计 | 36次DUT、5115比较 | 36次DUT、5115重复比较 | 合计72执行；第二轮不是新独立样本 |
| 规格重建 | 6MD、6WaveJSON、6SVG | 18文件逐字节相同 | 注册write-spec，固定WaveDrom3.6.1 |
| 浏览器检查 | 六张最终SVG逐张实际查看 | 截图与SHA随公开包保留 | 无新DUT/API，不是H02 |

累计器覆盖64个clear/enable/event四态组合，计数初态1与15按组合交替使用；并非64组合与两初态的完整交叉。另有8种未知复位场景，不是全部复位控制交叉。流水线覆盖64个reset/flush/valid四态组合及四个有效历史状态、六种负载图案，未穷举所有256个数据字。四态驱动器内置assert为0，结果由驱动器外的逐行比较判定，原采样和比较脚本全部保留。

官方门禁CLI没有导入真实仿真证据的参数，原JSON的`testbench/toolchain`维持`not_requested`。另存Icarus实际编译、运行和采样证据，不改写原门禁状态，也不宣称八项全通过。
