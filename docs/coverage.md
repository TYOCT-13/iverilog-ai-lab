# 信号活动覆盖率

更新日期：2026-09-11
实现位置：`src/iverilog_ai/core/coverage.py`（VCD 侧的取值统计在 `core/vcd.py`）
测试：`tests/core/test_coverage.py`（8 项）
报告章节：`### 信号活动覆盖率（激励质量）`

## 一、为什么是这个口径

Icarus Verilog **没有**内建代码覆盖率（语句 / 分支 / 条件 / 翻转），也没有编译期插桩。
因此本项目**不去伪造"代码覆盖率"**，而是做一个能用现有证据严格算出来的口径：

> 本次仿真中，RTL 里每个信号是否在 VCD 中产生过变化；到达过多少个不同取值。

它回答的问题很具体：**我写的激励，到底让设计里哪些部分动起来了？**

## 二、必须说清的边界（写进报告免责声明）

| 本覆盖率**能**说 | 本覆盖率**不能**说 |
|---|---|
| 某信号在本次仿真中是否变化过 | 某一行代码是否被执行（语句覆盖率） |
| 信号到达过多少种取值 | 某个分支是否被取过（分支覆盖率） |
| 覆盖率随激励变化，可用于比较激励质量 | 某个条件的取值组合是否全覆盖（条件覆盖率） |

三条容易误读的地方，报告里都明确写了：

1. **信号未变化 ≠ 死代码**：只表示本次激励没触发它；
2. **信号有变化 ≠ 逻辑被验证**：复位把信号拉低也会让它"变化"；
3. **只有被 ``$dumpvars`` 记录的信号参与统计**：未 dump 的层次显示为"不可观测"，
   而不是被算成"未覆盖"——这两者含义完全不同。

## 三、两个指标，以及为什么必须要第二个

### 指标一：信号活动比例

`发生变化过的信号数 / 声明信号数`。

**它单独用是不够的。** 实测：`mod10_counter` 在"只保持使能为 0、从不计数"的弱激励下，
活动比例仍然是 **100%**——因为复位把 `count` 清了一次零，它也算"变化过"。

### 指标二：取值覆盖

`信号到达过的不同取值数 / 该位宽类型的可能取值数`。

同一次对比：

| 激励 | 活动比例 | 取值覆盖 |
|---|---:|---:|
| 充分（复位 + 计数 + 保持） | 100% | **38%** |
| 弱（只保持使能为 0） | 100% | **6%** |

`mod10_counter.count` 在弱激励下只到达过 1 个取值（16 个可能取值中的 1 个）。
**取值覆盖才让"激励是否走到"变得可观测**，因此两个指标并列报告。

## 四、实现中修掉的两处会误导的地方

### 1. 编译期常量被当成"未变化的信号"

`traffic_light_emergency` 里的 `localparam RED=2'b00, YELLOW=2'b01, GREEN=2'b10` 是编译期
常量，**按定义永不变化**。早期实现把它们计入信号集合，于是报告出现 7 个"未变化信号"的
假缺口（覆盖率被压到 50%）。

修法：单独解析 `parameter` / `localparam` 声明并在统计中排除。这里还有一个次生 bug：
用"名字列表"正则去匹配声明时，`RED=2'b00, YELLOW=...` 里每个名字后面跟的是 `=`，
名字列表正则在第一个名字后就匹配不下去了，只得到 `RED` 一个。改为取整条声明到分号、
按逗号切分后逐个取 `=` 左侧的名字。

### 2. 存储体被计入信号集合

`reg [7:0] mem [0:3];` 在 VCD 里通常按字展开，整体名不一定出现，会被误算成"未覆盖"。
现在单独识别为 `excluded_memories`，并在报告里说明原因。

### 3. 1 位信号的取值覆盖显示为 None

标量声明（`input wire clk`）的位宽回退正则要求以 `;` 结尾，而 ANSI 端口列表里是
**逗号**分隔（`module m(input wire clk, input wire [3:0] d);`），于是 1 位信号被算成
"位宽未知"、取值覆盖列显示 `None`。修正为同时接受 `,` `;` `)`。

## 五、实测结果（全部参考设计）

用固定矩阵的产物统计 13 个不同 RTL：**全部为 100% 活动比例**——说明现有激励确实把
每个参考设计的信号都驱动到了。取值覆盖按信号位宽给出，例如
`traffic_light_emergency` 的 `state` 与 `next_state` 都到达了 4/4 个取值。

这个结果本身也是有信息量的：**它说明基准集的激励是充分的**，而不是"指标没在工作"——
第四节的三条修正和第三节的弱激励对照都证明了指标确实有区分力。

## 六、怎么用

流水线自动计算并写入 `vcd_analysis["coverage"]`，报告里渲染为独立章节：

```powershell
python -m iverilog_ai plan-run --plan <plan.json> --contract <contract.json> --rtl <dut.v> ...
# 报告里会出现「### 信号活动覆盖率（激励质量）」
```

Python API：

```python
from iverilog_ai.core.coverage import analyze_signal_activity
report = analyze_signal_activity(rtl_source, vcd_analysis, top="tb_pwm", instance="dut_i")
print(report["ratio"], report["value_coverage"], report["unchanged"])
```

## 七、后续可做的（本轮未做）

| 项 | 说明 | 前置条件 |
|---|---|---|
| 翻转覆盖率 | 统计信号 0→1 / 1→0 两个方向各发生过没有 | 简单，可在现有实现上加一个维度 |
| 状态机状态覆盖 | 识别 `localparam` 状态编码，报告哪些状态到达过 | 需要状态识别启发式，容易误判 |
| 真语句/分支覆盖率 | 需要编译期插桩或支持覆盖率的仿真器 | Icarus 不支持；要换工具或自己插桩 |
| 覆盖缺口 → 激励建议 | 把"哪些取值没到过"反馈给规划器补激励 | 依赖前几项的口径先稳定 |
