# ICARUS v4 答辩讲稿

## 01 ICARUS

本作品面向数字 IP 验证，把 AI 放在测试探索环节：模型根据公开规格提出输入序列，真实 Icarus 编译与仿真执行这些输入，独立判据逐拍决定是否存在差异。作品的重点是验证工具链如何让模型建议变成可核查的执行证据。AI 服务采用第三方 DeepSeek API，用户要求的配置为 4.1f，历史回执报告模型名 deepseek-flash。没有训练或微调模型权重，也没有把模型自述作为功能正确的证明。本次材料整理日期为 2026-10-13，实验成绩保持其原始批次和版本身份。

## 02 数字 IP 的时序验证需求

数字 IP 的错误常落在连续周期之间。流水线需要检查 valid 与 data 的两级对齐，flush 优先级以及 invalid 时的数据归零。事件累计器需要检查使能条件、模 16 回绕以及 clear 不受 enable 限制。固定测试能覆盖已知边界，随机输入能探索更多组合，AI 根据规格和实际执行摘要提出下一组刺激，价值需要通过统一实验验证。本项目的使用对象包括数字电路学习者、小型 IP 开发者和技术复核人员。需求来源为项目合约、真实执行与异机用户问题，未提供行业访谈样本或工业效益量化。

## 03 测试探索与独立裁决

模型只接收公开接口合约、自己的计划、剩余预算与允许的执行摘要。目标 RTL、私有变体标签、路径和 witness 不进入 API。系统对动作格式、接口与预算进行检查，再调用真实 Icarus，并使用从合约建立的独立判据核对实际输出。正确 RTL 按每个 episode 独立重放。AI 可以追加输入或停止，但不能改写结果。该分工是本作品 AI+IC 的主要结合点，也决定了错误归因：模型提案失败、环境或编译失败、功能差异和证据完整性是不同状态。

## 04 验证链路的迭代过程

迭代依据真实问题记录。早期流水线实现后，逐拍检查与独立 oracle 暴露规格及参考模型共享错误。随后增加协议判据、类型化动作、严格格式恢复和统一预算。多批 Agent 对照分别归档，最新实验的 Agent/helper/系统提示仍冻结为 a969337，实际新模块批次源码为 20400fa。之后干净 checkout 与跨平台 Actions 暴露盘符、编码、浅 Git 历史和字体等假设，推动工具自动发现。2026-10-13 的异机真人操作又暴露安装、入口和缺失 RTL 依赖，推动编译预检查与界面修改。此过程说明软件如何改进，不把不同批次拼成 AI 效果增长曲线。

## 05 规格与接口前置校验

执行前先检查公开规则、端口、时钟与复位配置。用户上传的 RTL 可能存在缺失依赖，文件名和合法 module 名不同本身并非编译错误。真实异机用户只上传 onewire_byte_controller.v，其 module one_wire_master_byte 实例化 one_wire_master_bit，两次运行都因为缺少后者停止。编译预检查在付费调用或正式仿真前暴露这类问题。计划中必须有可依据规格核查的 expected 或断言；没有输出判据的观察语句和零比较不能算功能通过。工具自动发现缓解开发机固定盘符在异机上失效的问题。

## 06 有界测试规划

模型提议计划并不意味着计划直接获准执行。类型化动作限定 append 或 stop，严格解析后再检验接口和预算。动作格式失败可以在原任务共享请求上限内补提，补提仍属于新的收费请求。单次 API 策略共享请求上限为 1，反馈和无反馈 Agent 为 3，episode 上限对应为 1 和 3，累计刺激拍上限为 24。每次提案向量上限 12，累计接受上限 64。输错格式、越界预算、重复提案和停止都保留真实状态；有界恢复不等于无成本重试。本项目没有自动传输重试。

## 07 FIFO 独立队列判据

FIFO 旧 RTL 与旧 reference model 曾共享计数错误，说明仅比较两个相似实现可能漏掉共同错误。独立 deque 规格检查中间占用时的同时读写：第 5 拍读出 25、写入 99，队列从 [25,66] 变为 [66,99]，占用量从 2 保持为 2。第 7 拍首次出现 full 端口差异，旧实现为 0，独立队列应为 1，修复后为 1。同一组 76 拍与 228 次输出比较，差异从 66 减到 0。该页是人工规格与实现修复案例，不能算 AI 自动发现缺陷或工业性能收益。外部人工 SPEC 补全另有 13/15 到 15/15 的历史记录，同样不属于 AI 表现统计。

## 08 带真实端口事实的反馈循环

反馈循环先实际执行，再把有限端口事实投影给模型。最新批次共保存 80 份端口文档，826 个有限原始采样中返回 701 点、注明省略 125 点。实际付费模型输入只有反馈策略的 20 个后续 STATE 携带端口事实，合计返回 180 点、省略 12 点。每份最多 12 个端点与等间隔样本，保留省略和 X/Z。无反馈策略的 31 个已发送 STATE 中 observation、plan_error、latest_decision_error 均为 None，但自己的计划、剩余预算和执行器早停仍保留。两个新模块的功能覆盖状态为 unsupported/unknown，不能补造命名 bins。反馈对照仍不足以证明因果收益。

## 09 请求预算与付费失败留存

最新独立单批上限为 1,000,000 tokens，实际 87 次收费请求，模型报告输入 301,910 加输出 37,714 等于 339,624 tokens。没有 unknown/pending 用量和自动传输重试。本实验记录为 87 份原响应，其中 86 份 JSON 可解析、1 份不可解析。产品的原文留存受安全策略约束：安全响应可以保留原文，阻断内容只保留 SHA、长度和原因码，不承诺无条件保存所有响应原文。85 个响应通过 schema，2 个格式拒绝。5 个预算拒绝属于 schema 通过子集，不能和 85 加 2 再相加。终态第 108 行先实际执行 14 拍，再遇预算拒绝，第三请求格式失败后达到共享请求上限，保留 decision_format_error 并计入完整分母。模型报告 tokens 是用量口径，不等同于第三方账单。

## 10 最新 108 任务的对照设计

最新集合由 valid_data_pipeline 和 event_accumulator 两个新内部模块组成，每模块正确目标与 B/C 缺陷目标各重复三次，对比固定、均匀随机、协议随机、单次 API、反馈 Agent 和无反馈 Agent 六策略。2 模块乘 3 目标乘 3 重复乘 6 策略等于 108 任务，全部实际执行。每策略 4 个不同缺陷乘 3 重复等于 12 缺陷任务，另有 6 个正确任务。每任务共同使用最多 24 刺激拍的上限，single 最多 1 请求，反馈与无反馈 Agent 最多 3 请求，零 API 基线没有模型请求。这些是共同上限和不同策略权限，不能解释为实际等耗费：六策略累计实际刺激拍分别为 432、432、432、236、300、290。集合由同团队合成，Agent 冻结在新模块之前，但没有独立选型时间戳、外部盲测或预训练未见证明。该设计只能支持这组模块、参数、预算和有限刺激拍内的描述结论。

## 11 最新批次的六策略检出

六策略在统一 12 缺陷任务分母下分别检出 12、10、8、8、11、10。固定测试本次最好，反馈 Agent 11/12，仅比均匀随机和无反馈各 10/12 多一项。4 个缺陷三次重复不能当作 12 个独立缺陷，不支持显著性、因果或工业普适收益。每任务共同 24 拍上限，但 single 最多 1 次请求、Agent 最多 3 次，实际刺激拍与请求数不同，不能称等耗费对照。36/36 正确任务实际执行，实际误报为 0。全批 134 个审计 round、268 个 DUT/参考执行侧，strict_comparison_eligible=true 只表示完整证据资格，并不意味着所有动作成功。终态格式失败仍在分母中。图表使用原生可编辑数据对象，和历史批次分开展示。

## 13 执行记录与原件绑定

证据从冻结登记输入开始，共 458 项，真实执行与请求保存 4,359 个 raw 文件，再用 manifest、ZIP 和 SHA-256 绑定原字节。Git 绑定 446 exact、12 项仅换行差异，因此原始登记快照仍是权威，不能称干净 checkout 每字节一致。核心审计由非实现者代理完成 2,192 项机器检查，包括 1,923 加 269；轨迹审计由实验 entry 代码作者检查 54 条轨迹和 87 次请求。核心重算 6,214 项输出并检查 27,434 个 VCD 端口值。机器审计没有追加 API 或 DUT，并不等于真人独立审核 H02。安全策略允许的失败原文与执行记录进入证据链；阻断响应只留 SHA、长度和原因码。拒绝、缺少执行与失败状态仍保留，不因不能公开原文而消失。

工程能力包括工具自动发现、干净 checkout、Windows/Linux CI 和验证门禁。历史提交 216438d9a434702ec0fcf41bdaac68aea8c2e5c8 确有 5 个 jobs 全绿：verify 37754301009 为 2031 pass、22 skip；CI 37754301011 的 Ubuntu Python 3.11/3.12 各为 2035 pass、18 skip，Windows Python 3.11/3.12 各为 2038 pass、15 skip。各 job 结果不能相加为独立测试总量。当前已推送提交 df7ccfa 的两条 Actions 工作流分别为 verify 38338658309 与 CI 38338659290，截至本轮核验均 completed/failure，Agent/helper 变更触发旧冻结实验夹具保护，因此本页明确写当前云端检查未通过。旧 v3 材料中的 2,033 pass、2 skip、mypy 88 文件零错误只是当时机器记录，不能直接替换成当前提交回归成绩，也不能把工程回归算作 AI 效果或用户成功。后续需要定位并修复当前提交检查失败，再独立保留新检查证据。

## 16 异机反馈推动的产品修改

反馈推动默认折叠端口与时钟表单，缩短首屏，调整生成 JSON 与校验入口，增加蓝色主操作辨识，并把校验放在执行前。编译预检查 f75f619 更早说明缺少模块，默认折叠和入口调整为 7059d25。工具路径改为自动发现或配置路径，替代开发机固定 D 盘假设。服务端默认输出上限 d9ffded 也已发布，界面的“无 token 上限”选择仍受实际服务端默认上限约束，不写成无限资源。开发侧修改与手册更新有提交证据，但尚未收到用户在同一电脑使用新版本复测成功的证据，不能把这些修改算成新增用户通过项。

## 17 AI 与 IC 验证的工程结合

可复用贡献在于把模型动作纳入工程约束：公开规格与接口约束降低无效输入，独立 oracle 阻断共享实现错误，严格格式有界恢复防止无界请求，账本保存预算和付费失败，原件绑定让结果能够核对。真实异机问题进一步推动界面与编译预检查。该组合覆盖了 AI 测试探索与 IC 实际执行之间的关键工程环节。当前实验仍未证明反馈的统计显著收益或工业普适提升；固定测试在最新集合检出最好。后续创新评价应结合独立新模块、多次重复、真实用户复测和明确成本，而不只挑选最高检出数字。

## 18 后续验证与交付路线

近期先修复当前提交云端检查，补齐真实 RTL 依赖与可执行 expected/断言，在新终端和同一用户电脑上保留新的复测记录，不回填历史失败。随后补全环境版本、实际协助、运行日志、比较数与 VCD，再安排独立人工审核。更广泛的 AI 效果研究需要预登记新模块、统一预算、多次重复和更大独立缺陷集合，分别报告成本与失败。官方截止已在本轮核验为 2026-10-30 20:00 北京时间。技术方案 PDF 不超过 10MB，答辩交 PDF，佐证合并一份 PDF，视频可选。缺少真实队号时保留内部文件名，不编造队伍身份。PPTX 保持标题、表格和图表可编辑，PDF用于答辩阅读。
