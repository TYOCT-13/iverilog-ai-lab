## 2. 证据分类不可混用

| 类型 | 可以做的事 | 不能写成 |
|---|---|---|
| 自动化测试 | 固定输入、脚本、仿真、接口及状态检查 | 真人试用或真实用户满意度 |
| 代理操作/代理交叉检查 | 按任务操作、审查代码和结论，记录实际异常 | 独立人工审核、用户原话或行业调研 |
| 真人试用 | 记录真实使用者任务、操作、用时、求助及意见 | 产品全部技术指标已被证明 |
| 独立人工复核 | 核查规格、判据、变体、统计和可复现性 | 认证机构鉴定或工业签核 |

不能提前取一个理想结果。失败、跳过、预算耗尽和不确定都保留；修复后的复测另列。小样本的结果只描述相应样本。真人数据不足时直接声明缺口，不用模拟角色填补人数和引语。

## 3. 真人参与的最小可执行安排

以下是资源有限时的组织建议，不是赛事硬性人数要求，也不能代表充分的用户研究。

1. 找至少一名未参与对应页面开发的实际使用者，发送[参与者入口](../../trial/participant_start.md)与 T02、T03、T07、T08；不提前给组织者答案。记录匿名代号、设备、版本、录屏与引用意愿。
2. 由其独立完成选择案例、解释缺陷结果、切页返回和证据导出。观察者记录开始/结束、卡点、提示与代操作；共享机器试用不写成独立安装成功。
3. 使用者填写原始反馈，组织者转录后请本人核对。截图与用时来自实际会话；拒绝公开的内容只保留私有记录。
4. 另找一名非被审核功能实现者按[独立审核指南](../../review/independent_review_guide.md)检查一个正确模块、一个缺陷、一个不可判定场景；先核对规格和期望，再重放，并抽查一项统计。
5. 保留异议。修复后使用新版本复测，首次失败不能删除。仅有一人时披露样本局限和审核关系，不称为独立第三方认证。

完整方案见[试用材料](../../trial/README.md)。代理可准备材料、整理授权范围内的原始证据、复算统计，不能代替参与者确认其体验。

## 4. 提交规格

实际查阅日期：2026-10-04。规则要求以原文及报名系统最终字段为准：

- [x] 本地名称15字符、简介192字符，均在20/300限制内；报名系统尚未提交。
- [x] 技术方案工作稿为PDF，369 KB，按七节大纲组织；最终团队编号与定稿另核对。
- [ ] 答辩材料导出 PDF。
- [ ] 如提供视频：MP4，3–5 分钟，300 MB 以内。
- [ ] 佐证材料合成一个 PDF；不存在未获授权的身份信息或虚构用户证明。
- [ ] 评审方案、视频和答辩稿中无学校名称、校徽和指导教师信息。
- [ ] 大型文件分享有效；按规则统一文件名并检查提取码、有效期和干净浏览器下载。
- [ ] 提交前核对报名状态与真实团队编号。官方通知的报名和初赛提交截止为 2026-10-15 20:00。

通知允许报名多个赛题，不代表已报名作品可直接跨赛道复用、已支付费用能自动转移或系统已完成转赛道。相关操作需在报名系统或联系组委会确认；代码改造不等于报名变更。

## 5. 最终口径检查

- [ ] `83/83` 明确为历史手写测试台基准，未描述成 AI 成绩。
- [ ] 历史在线规划与新反馈 Agent 分开；不同轮数的并集没有冒充同总预算比较。
- [ ] 单个缺陷的多个失败检查没有被重复统计为多个缺陷。
- [ ] “输入下未发现差异”没有写成形式等价或完整正确性证明。
- [ ] 第三方模型/API、Icarus、外部 RTL 与许可清楚；无自研权重的虚假表述。
- [ ] 没有全行业无测试台、业内首创、替代签核等缺乏来源的主张。
- [ ] 原始产物在忽略目录中的事实已披露，提交包实际包含可共享的证据。
- [ ] 新实验结束后按实际结果修改本稿；未完成项没有被勾选。
