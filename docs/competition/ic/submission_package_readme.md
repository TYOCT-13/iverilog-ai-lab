# ICARUS 报告材料包使用说明

日期：2026-10-04。本次按“真人试用、独立人工复核均通过”的前提完成提交格式稿。所有机器数据沿用真实记录，H01/H02 仍保留条件标识；实际原始证明未提供。本地材料已生成，不代表报名系统已经提交。

## 1. 文件与提交位置

| 材料 | 文件 | 用途 |
|---|---|---|
| 技术方案 | `ICARUS_技术方案.pdf` | 技术方案字段；七节大纲，含架构图、五策略图和证据索引 |
| 技术方案源稿 | `report_submission.md` | 后续根据真实原件修改，重新导出PDF |
| 佐证材料 | `ICARUS_佐证材料.pdf` | 已合并机器证据、实际截图及H01/H02待补原件说明 |
| 佐证源稿 | `supporting_evidence_submission.md` | 在相应位置补入经过核实、授权与脱敏的真人、人审原件 |
| 报名短文本 | `submission_copy.md` | 复制作品名称与简介 |
| 本地技术证据包 | 见 `evidence_pack_2026-10-04.md` | 包内源码和原始产物；保持既有ZIP只读 |

技术方案和佐证PDF采用匿名版式，元数据不填写作者或单位。原工作稿、原始实验和既有冻结包没有覆盖。新材料产生于材料提交 `81114bce` 之后；最终工程回归仍对应源码 `867b8bd`，没有为写报告新增API请求或重算旧成绩。

## 2. 将条件稿转成事实稿

1. 核对H01真人记录：实际参与者、任务、版本、环境、协助、首次失败与复测、反馈原件及引用授权。分母保留全部实际分配任务，缺记录单列未知、不计成功；未分配任务不纳入。
2. 核对H02人审记录：审核范围、与开发工作的关系、规格与判据、重放日志、统计抽查、异议及最终确认。代理报告不可作为审核者签署。
3. 若原件确认通过，按真实范围替换技术方案5.4和佐证H01/H02段落，并附实际原件。只有完成核实后才能更新封面和页眉的条件稿标识；若结论不同，按实际结果修改。
4. 核对真实团队编号、最终版本与报名赛题。评审PDF只使用作品和团队编号，报名系统身份字段另填。
5. 重导出两份PDF并重新检查版面、引用、匿名性、体积和材料集合，不直接编辑已有PDF正文。

这项替换不改变E03的4/8或E04的13/15，也不证明新增AI优于固定/随机。没有原始计时和账单，不填写节省时间、节省费用或经济收益。

## 3. 官方格式与命名

技术方案为PDF、10M以内；名称不超过20字、简介不超过300字；答辩文件导出PDF，佐证材料合并为一个PDF。视频如提供，为3-5分钟MP4、300MB以内。正式格式与匿名要求依据[官方通知中的附件1](https://www.aicomp.cn/notice/4756.html)，本次查阅于2026-10-04。

真实团队编号确定后，按官方命名结构重命名，例如：

```text
真实团队编号-AI+集成电路-ICARUS数字IP验证智能体-技术方案.pdf
真实团队编号-AI+集成电路-ICARUS数字IP验证智能体-佐证材料.pdf
```

上面的“真实团队编号”是命名说明，不是已经填写的编号。大型代码和工程文件按规则提供有效分享链接；当前不生成虚构仓库URL、分享地址或提取码。

## 4. 本轮检查与尚缺材料

新PDF的页数、体积、源码哈希和版面检查统一登记于 `submission_validation_2026-10-04.json`。三尺寸浏览器截图来自已有E07记录，没有改为“真人截图”。技术方案和佐证材料分别保留H01/H02条件标识。

两份PDF分别为11页和5页，全部16页已经渲染后查看。本地报告材料压缩包为 `.iverilog-ai/ic-submission-materials-20261004.zip`，含本轮PDF、源稿、配图和校验回执；不是完整工程复现包。重新生成源稿仍需在项目中使用其原证据和截图，完整技术原件见既有冻结证据包。

本轮没有制作答辩PDF或录制演示视频，也没有完成远程分享与报名上传。这两份PDF构成本轮请求的报告材料；答辩和视频可沿用真实功能、同一实验口径与原有录制指南另行制作。

## 5. 重新生成

在项目根目录执行：

```powershell
python scripts/markdown_to_pdf.py docs/competition/ic/report_submission.md docs/competition/ic/ICARUS_技术方案.pdf
python scripts/markdown_to_pdf.py docs/competition/ic/supporting_evidence_submission.md docs/competition/ic/ICARUS_佐证材料.pdf
python scripts/check_submission.py --kind report docs/competition/ic/ICARUS_技术方案.pdf
```

每次改动后须重新渲染查看，不只依据退出码。原始证据和首次失败记录保持原样；材料更新使用新的验证回执。
