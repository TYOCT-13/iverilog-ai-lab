## 一、作品概述

### 1.1 背景与问题

数字 IP 开发需要判断 RTL 是否符合接口和时序行为要求。能编译只说明工具接受代码，不能说明复位、边界条件、握手或状态转移正确。通用模型可以协助提出输入序列，但模型同时生成的预期输出需要独立核对；否则计划合法、仿真成功和功能正确容易被混为一谈。

本项目将需求限定在设计阶段的模块级功能验证，提供从规格和接口到输入计划、真实仿真、结果解释与证据导出的工作流。首批对象为需要验证小型数字 IP 的开发者和学习者。复杂 SoC 验证、时序签核、形式验证及制造测试不属于本版本目标。

### 1.2 目标与作品形态

用户选取案例或上传 RTL，确认接口与验证目标后，模型通过 API 提出测试输入；系统校验动作并调用本地 Icarus。具备参考模型时，由确定性逻辑生成期望结果并比较实际输出。模型读取摘要后追加测试，直到发现反例、主动停止、遇到错误或预算耗尽。

作品包含 Streamlit 网页、CLI、Python 验证库、案例与规则、实验脚本。开源交付支持复现和二次开发；参赛主线是 AI 对集成电路设计验证流程的辅助作用。

目标分为三个层次：

| 层次 | 验收内容 | 当前证据状态 |
|---|---|---|
| 可运行 | API 生成计划、真实仿真、反馈补测与证据保存 | 内置单模块与四类模块真实API pilot已完成；外部类型化采样修复及1请求/2轮真实API联调已完成 |
| 可核验 | 期望值来源、输入版本、失败与停止原因可追溯 | 代码、回归及联调记录可查；原始目录需随交付打包 |
| 有增益 | 在相同预算上限下改善缺陷检出、减少无效操作 | 反馈Agent为4/8，高于单次/无反馈的2/8，但低于固定/随机5/8；仅为单次开发集观察 |

## 二、需求分析

### 2.1 需求拆解

| 具体任务 | 难点 | 产品响应 | 尚需补充的使用证据 |
|---|---|---|---|
| 验证复位、使能、边界与握手 | 合法输入不一定覆盖关键行为 | 规格约束计划，保留旧向量并追加测试 | 实际 RTL 使用者如何选择验证目标 |
| 理解失败 | 编译错误、仿真错误与功能差异含义不同 | 分别保留错误、检查记录与波形 | 使用者能否正确解释“未发现差异” |
| 复查 AI 提出的测试 | 模型输出可能结构不合法或判断不可靠 | Schema 门禁、独立期望值、动作权限限制 | 补测是否覆盖了原计划遗漏的场景 |
| 控制执行成本 | 多轮调用和重复仿真消耗时间与用量 | 请求、轮数、激励周期与超时限制 | 在真实任务中的等待是否可接受 |
| 复现同一结论 | 输入或版本变化后旧结果可能失效 | 输入哈希、轨迹、每轮产物与状态清理 | 异机是否可从证据包重放 |

### 2.2 待收集的需求与试用证据

真人需求记录需包含角色、开发关系、具体任务、现用方法、遇到的事实、希望改善的步骤及匿名引用授权。暂不填写人数、原话、满意度、节省时间或效率百分比。

## 三、AI 技术工具选择与运用

### 3.1 模型与工具角色

当前在线联调采用第三方模型 API，配置模型 ID 为 `deepseek-flash`。不在本机部署模型，不宣称自行训练基础模型权重。选用 API 是为了复用语言与推理能力，将工程工作集中于验证约束、执行与证据管理。模型名称及当次配置以轨迹为准，服务商后续更新不能追溯覆盖历史记录。

Icarus 负责编译和执行测试台；其退出成功本身不构成功能正确证据。独立参考模型提供当前支持模块的期望输出，比较逻辑给出检查结果。Python/Pydantic 负责类型与动作约束，Streamlit 提供操作入口。第三方来源及许可参照项目资源清单，发布时附对应版本。

### 3.2 模型可以做什么

模型输入包括人工规格、接口合约、现有计划、最近一轮仿真摘要和剩余预算。允许动作是追加输入向量或停止。不得输出 shell 命令、改 RTL、改参考模型、替换旧向量或指定期望输出。新增动作通过校验后才进入仿真。

模型提供候选测试，不能为自身输出建立可信判据。内置流程缺少独立参考判据时停止并提示证据不足，不把生成的期望值当作真值。新增外部流程采用明确不同的 `qualified_baseline_differential`：基线先通过已有有限规格检查，再在同一输入下比较限定输出。它报告 `behavior_difference`，不将差异直接标为功能反例。预算耗尽和未发现差异均不代表全部行为正确。

## 四、项目实施

### 4.1 执行流程

```text
RTL＋人工规格＋接口合约
    ↓
API 提议追加输入 / 停止
    ↓
结构、动作、输入哈希及预算检查
    ↓
生成测试台 → Icarus 编译与仿真 → 独立判据比较
    ↓
保存计划、日志、波形、检查结果与轨迹
    ↓
反例 / 错误 / 证据不足 / 预算耗尽：停止
否则：将摘要反馈给 API，继续下一轮
```

### 4.2 关键实现与改进点

1. **将输入提出和结果判断分开。** 模型负责测试输入，确定性参考模型负责期望输出；判据的支持范围对用户可见。参考模型本身仍需独立核查。
2. **在真实仿真反馈上补测。** 后续动作保留已有输入，以追加方式扩展计划。遇到反例保留现场，不通过改变预期结果掩盖失败。
3. **以可复核的运行记录约束自动化。** 每轮保存实际计划、检查数、失败数、停止原因和输入哈希，使模型建议与执行事实分开。
4. **明确有限预算。** 请求失败也消耗调用尝试；累计激励周期计入每轮重放的旧计划。它不包含全部复位开销，不是代码覆盖率，也不是金额封顶。

这些是本项目的工程设计和差异化组合，不据此宣称“业内首创”或“替代验证工程师”。已有单次开发集消融不足以证明反馈机制的普遍价值，仍须增加重复与独立留出任务。

### 4.3 状态、异常与安全边界

网页保留同会话页面切换和 rerun 的结果；设计输入变化会清除相关旧页面证据，磁盘记录保留。新执行使用新目录，避免覆盖历史轨迹。API 输出不合法、截断、网络错误和仿真错误分别记录。密钥由本机私有配置读取，不能写入提交材料。

轨迹默认在本地忽略目录中，不自动上传训练。候选数据导出仍待人工标注；本次没有模型微调成果。运行时间预算在操作间检查，单次 API 与仿真另设超时，不宣称严格可中断所有阻塞。

当前内置判据另收紧两项语义：顺序逻辑的 `before` 采样不再给出 `reference_model` 判定，而是明确缺少证据；输入向量未重复列出的值按测试台语义保持先前值。这是源码提交 `1c1e0dc` 的修正，下面60行pilot仍为 `e9b7b8a` 冻结运行，未在新判据下重新实验，不能把旧成绩当成新源码的能力成绩。

### 4.4 外部 RTL 类型化适配

外部输入先按清单验证源码哈希，再运行已有规格测试确认基线在这些检查下零失败。适配器目标是在测试台实际采样时刻比较顶层限定输出；对于 valid 为零且规格未定义的数据，不比较其无效载荷。初版从 VCD 同一时间戳读取最终值，后续自审发现这不一定等于采样语句瞬间值：下一向量引起的组合变化可能污染采样。现已改为采样语句之后、下一组输入之前记录即时快照，并保存插桩前后测试台和哈希；锚点或样本数不符即拒绝。初版优先编码器16个采样点中实际发现4个与快照不同，旧证据保留，新目录重新验收。历史外部 UART TX 与内置案例同名，适配器显式禁用不适用的内置参考模型映射。

外部证据的 `checks/failures` 保持零，另列 `compared_samples/differences`，不将波形样本伪装成独立断言。候选和基线各消耗一次仿真预算；规格资格检查与复位开销另行披露。即时快照修复后24项适配测试通过，外部UART RX真实API联调已完成1请求、2轮；完整事实见第五节。[外部适配说明](../../experiment/external_api_agent.md)

### 4.5 多模块 pilot 与后续正式实验

冻结模块、变体、判据和版本后，比较固定输入、随机输入、单次 API、多轮无反馈 API 与多轮反馈 Agent。对齐累计激励周期，披露实际请求、token、耗时与失败。至少分别统计参考实现误报、变体检出、不可判定和未执行；多条失败检查不能当作多个独立缺陷。

当前 pilot 预注册四类模块、八个缺陷、五种策略，共六十个样本，单次重复；以相同累计激励周期上限比较，不宣称实际周期、采样次数、token 或总耗时完全相同。多周期向量只在结束时检查，随机逐周期输入的采样更密；发现反例即停止，因此后续反馈主要是无差异摘要，不能宣传为失败日志驱动修复。首轮因接线配置问题主动停止并单列，新目录 `.iverilog-ai/agent-comparison-live-chat-v2/` 已完整结束，52次实际请求，冻结输入变化列表为空，结果见第五节。[协议](../../experiment/agent_comparison_protocol.md)、[代理交叉检查](../../review/agent_comparison_cross_review_2026-10-04.md)

开发时已查看过的设计不能重新包装成独立留出集。若多轮次数不同，不比较累计并集来宣称同预算优势。保留全部预定任务及失败，不挑选“理想但不完美”的样本。任何重跑记录修正原因、版本与首次结果。

### 5.3 外部UART RX真实API联调

真实服务商调用1次、Icarus执行2轮，累计782个双侧激励周期，usage为5,661 tokens。已有固定计划182周期/侧，547个有效输出比较；追加4个向量后209周期/侧、628个比较，两轮均0差异。资格规格检查11项通过；候选和基线为相同冻结字节，所以这里只证明追加输入、双侧仿真和记录链可运行，不证明准确率。

另用固定和API扩展计划离线重放历史位序变体，两者均在cycle80、836ns观察到同一差异（数据150与105）。固定计划本来就能发现它，不能归功于新增AI向量，也不能称为API新发现缺陷。周期计入重放，资格检查和复位开销另列；达到轮数上限而停不证明完整正确性。[真实联调记录](../../experiment/external_agent_live_2026-10-04.md)、[原件核查摘要](../../experiment/external-agent-live-2026-10-04/summary.json)

### 5.5 真实失败与修正

首次联调的第二次响应结构校验失败。原记录仅保留异常类别，没有足够字段诊断及用量，无法确认具体错误字段或是否截断。后续同时调整提示词约束与输出上限，并补充安全诊断；不能把成功单独归因于某一项改动。有效响应已记录的 token 不包含首次失败请求的未知用量，不充当总账单。

另一次多模块首轮 runner 使用的默认协议与此前联调配置不同，执行者主动停止。原始 60 行保留；有 7 次已记录响应、51,433 个已知 tokens，另有一次可能在途请求状态与用量未知。观测到截断和 JSON 校验失败，但没有可重放正文，不能认定协议差异是所有错误的唯一原因。该轮是接线失败开发记录，不并入后续完整 pilot。[首轮停止记录](../../experiment/agent_comparison_interrupted_2026-10-04.md)

### 5.6 当前缺少的成效证据

真人使用时间、无人协助完成率与独立人工复核尚未形成本文可引用的完整证据。内部pilot、外部即时采样与真实API联调已有记录，但新内置判据修正后的能力重测、更多重复、独立留出集和有限规格判据人工核验仍待完成。后续新增结果应提供完整任务清单、原始文件哈希、复现入口、失败分类和版本；不得只写一个最终成功率。

没有实测经济效益，本文不填写节省人力、降低成本或量产收益。当前价值在于提供可执行、可追踪的模块验证流程；能否减少真实使用者工作量需要试用确认。

## 六、总结与展望

本作品已将第三方 API 的输入规划与本地 RTL 仿真结合，形成带判据和预算约束的自动补测流程。工程实现、历史基准、单模块联调及四类模块pilot具备记录。本轮反馈Agent没有胜过固定和随机策略，改进方向须以实际漏检、输出失败和判据假警为依据。不同证据不能合并成更强的准确率主张，也没有本地模型权重训练成果。

主要局限是参考判据支持范围有限、模型输出存在失败、开发集与留出集仍需严格划分，以及缺少真实用户和外部人工核查。正式报名/赛道变更、远程开源发布和最终提交包验收仍待完成，本机Git提交不等于已公开发布。短期优先扩展模块及判据、完成反馈消融、处理用户实际卡点；之后再评估托管微调是否带来可重复收益。上板、形式验证和商用签核兼容性属于后续研究方向，不作为本版本已交付能力。
