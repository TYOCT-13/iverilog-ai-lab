# ICARUS v3 常见追问与证据定位

下列回答用于答辩讨论，不替代原件。材料制作本身没有追加 API、读取凭据或运行 DUT。

1. **模型会判断自己生成的期望值吗？**  
   新批只允许追加输入或停止。受支持合约的全部输出由冻结参考判据逐周期检查，并在正确 RTL 上独立重放。模型收到公开规格和完整合约，不收到私有目标 RTL、变体标签、witness 或路径。证据见 trace-audit.json 的模型状态及 body SHA 绑定。

2. **strict=true 是不是表示 108 行都成功？**  
   它表示内部完整证据资格满足。108 行均执行，但第 108 行终态 decision_format_error，仍有此前 14 拍实际执行且保留未检出分母。不能把资格字段解释为动作全部成功。

3. **反馈 11/12 是否证明比随机更好？**  
   固定测试为 12/12 最好，均匀随机和无反馈各 10/12。4 个不同缺陷、3 次重复的差异只有 1 个任务，不支持因果、显著性或普适工业收益。重复不等于增加不同缺陷数量。

4. **两新模块真的是外部盲测吗？**  
   新成员与此前五个受控 API 批次不重叠，Agent/helper/System 在模块生成前已冻结。设计与变体仍由同团队制作，没有独立时间戳证明选型早于旧成绩，不能声称外部盲测或预训练未见。

5. **为什么不把旧 432 与新 108 合并？**  
   两批模块集合、缺陷分母和预算不同。旧每策略 48，新每策略 12，旧有 18 个零 DUT 项且 strict=false。两个批次保留各自完整分母，不能画成单因素增益趋势。

6. **格式拒绝后会无限重试吗？**  
   单次 API 仍至多 1 请求，反馈/无反馈至多 3 个共享请求。格式和预算补提都收费且计入原 cap，传输自动重试为 0。5 预算拒绝与 2 格式拒绝均在原任务上限中，没有独立补批。

7. **85+2+5 为什么大于 87？**  
   85 是 schema 通过，2 是 schema 拒绝。5 个预算拒绝是 85 个 schema 通过中的子集，属于后续计划预算拒绝，不能当成额外请求。

8. **付费失败保存了吗？**  
   87 原响应全部保存，86 可解析 JSON、1 不可解析。预算拒绝收费 23,991 tokens，格式拒绝收费 9,274 tokens。失败 raw、停止原因与账本一起进入 full_raw ZIP 和 manifest，不改写成成功。

9. **端口 feedback 的 complete 有多完整？**  
   只表示一个有限且 SHA 绑定的实际流。80 文档共 826 原采样，返回 701、省略 125，每份最多 12 点端点加等间隔。它不表示全部路径、全部参数或代码覆盖完整。

10. **无反馈是不是彻底什么都不知道？**  
    31 个已发送 STATE 的 observation、plan_error、latest_decision_error 为 None。自身历史计划、预算和执行器 early-stop 保留，其中 12 个状态仍有当前计划和减少后预算。这是受控对照，不是移除所有信息。

11. **24 个 bins 也覆盖两新模块吗？**  
    没有。24 bins 只覆盖旧四配置。两个新模块返回 unsupported/unknown，不补造 bins，也不宣称代码覆盖率。

12. **第三方模型具体是什么？**  
    用户请求 4.1f，第三方 DeepSeek API 返回 deepseek-flash。thinking disabled、非流式、4096 输出上限、60 秒超时、0 自动传输重试。作品未训练或微调权重，未提供本地基础模型。

13. **339,624 tokens 就是货币花费吗？**  
    不是。301,910 输入加 37,714 输出等于服务方 reported total，未知和 pending 为 0。没有服务商货币账单，不换算成未经核对的价格或节省比例。缓存字段不重复计入 total。

14. **审计是否独立真人审核？**  
    核心审计是非实现者代理的 2,192 项机器检查。轨迹审计由 entry 作者检查 54 条轨迹、87 请求，明确非独立于入口作者。两者都不是真人、独立人审或 H02。

15. **原件能逐字节绑定 Git 吗？**  
    458 登记输入中 446 与 Git blob exact，12 仅有换行差异。原始登记快照为权威，不能声称 clean checkout 每字节一致。4,359 raw 文件通过 manifest 与公开 ZIP 原字节核验。

16. **FIFO 和 13/15→15/15 是 Agent 的成绩吗？**  
    不是。FIFO 是人工独立 deque 规格检查后修复 RTL 与模型。外部 15 个历史人工变体的提升来自人工 UART TX 计时 SPEC 补全，在同字节输入上复放。原始来源来自同作者仓库，不是新外部盲测。

17. **真实网页截图为什么没放最新验证页？**  
    历史浏览器记录对应 28be1ed，0 API、桌面视口模拟、没有真人参加。v3 不用它冒充最新在线验证。本材料用新108的真实轨迹、计划和账本作为主要证据。

18. **还缺什么？**  
    硬件、异机 Actions、真人试用、独立人审原件未提供。严格 RTL 样式仍有 12 项，WaveDrom 3.6.1 缺失。机器工程 2033 pass/2 skip、mypy 88 和 535 指纹不变不能填补这些证据缺口。

19. **真人/H02 是官方硬门槛吗？**  
    官方规则未列为硬门槛。它们是项目内部补强证据项，目前如实未提供。官方要求见最终材料事实源中的通知、规则 PDF、技术大纲 PDF。

20. **答辩 PDF 可编辑吗？**  
    它由正式 PPTX 的完整 slide PNG 导出，是图像 PDF。PPTX 的正文、流程、表格和图表保留原生可编辑对象，图表嵌入 literal workbook。未做 Native Office 打开/编辑测试，需在目标机器进行最终展示检查。

21. **正式提交文件名怎么填写？**  
    按真实队号-赛题名称-作品名称-材料名称组织。真实队号尚未提供，内部文件暂称 ICARUS_答辩材料_v3，不以假队号替代。匿名页面也不填写机构、署名或签字。
