## 六、人工智能工具与服务

### 6.1 生成式 AI 工具使用说明

按规则第三条第（七）款要求说明如下：

| 环节 | 是否使用生成式 AI 辅助 | 团队审核与验证方式 |
|---|---|---|
| 代码开发 | 是。使用生成式 AI 编程助手辅助编写部分 Python 模块、Verilog 测试平台和文档草稿 | 全部代码由团队逐文件审核；**功能结论一律以本机 Icarus/vvp 的真实编译与仿真结果为准**，不以 AI 自评作为正确性证据；`tests/` 下 97 个自动化测试作为回归门禁 |
| 文档撰写 | 是。辅助起草中文文档结构 | 团队核对每条技术陈述与代码、实验产物的一致性；已删除与实现不符的表述 |
| 竞赛材料 | 是。辅助整理清单与报告结构 | 团队对来源、版本、许可证信息逐项核验（见本清单各行的核验依据） |
| 作品运行时 | 是（作品核心功能之一） | AI 只输出受严格 Schema 约束的测试计划；执行前必须通过 `TestPlan` 校验、DUT contract 匹配与路径安全策略；期望值由独立参考模型复算；**PASS/FAIL 只由 Icarus/vvp 裁决** |

**AI 生成内容不主张为团队自主知识产权**，其可用性已由团队通过编译、仿真与自动化测试逐项验证。

### 6.2 模型服务

| 项目 | 说明 |
|---|---|
| 默认配置 | 仓库默认使用**离线 `MockProvider`**，不请求任何网络服务，不含任何密钥 |
| 可选在线服务 | 用户可显式配置任意 OpenAI 兼容接口（如 DeepSeek）。**模型服务不是本仓库的依赖**：不打包、不绑定厂商、不在仓库内保存密钥 |
| 网络开关 | 除回环地址外，只有显式设置 `IVERILOG_AI_ALLOW_NETWORK=1` 才会发起网络请求 |
| 密钥处理 | API Key 只存在于进程内存或页面会话状态；不写入代码、`.env`、日志、报告或提交记录；子进程不继承密钥 |
| 数据外发 | 发往模型的内容限于：设计名、验证目标、DUT contract 摘要、脱敏后的失败诊断字段。**不上传 RTL 源码、不上传文件路径、不上传命令、不上传密钥** |
| 本地调试服务 | 仓库自带 `iverilog_ai.ai.debug_server`：只监听回环地址、不联网、不需要密钥，用于无凭据环境下的联调与回归。它不代表任何真实模型能力，其数据不作为 AI 效果依据 |

4. **未使用**任何需要商业授权、模型许可或数据许可限制的第三方资源。
