# 路线图完成度盘点与可加工作量清单

盘点日期：2026-09-10
对照文档：`docs/competition/scale_up_roadmap.md`（Codex 会话留下的阶段 1–8 清单）

本文只做两件事：把路线图逐条对照当前真实状态，然后列出**还没做、且能产生可核验成果**的加量项。所有状态都经代码与实跑核对，不凭印象。

`synth-delay`、`initial-block`、`missing-default-case`、`blocking-in-sequential`、
`non-blocking-combinational`、`incomplete-sensitivity`、`async-reset-no-sync`、

## 二、可加的工作量（按技术深度 × 可核验性排序）

### A. 参考模型逐拍对齐：把 12 套里的剩下 7 套做完

- **现状**：`uart_tx`、`spi_master`、`handshake_stage`、`debounce`、`pwm`、`sync_reset`、`mux4` 只做诊断，不能作为权威预言机。
- **做法**：已有可复用的对齐方法（`tests/core/test_reference_model_alignment.py`）——同一组向量同时喂模型与 RTL，逐拍比较可观测输出，要求多 seed 零差异。`sync_fifo` 就是这样对齐的，并顺带发现三条真实语义（含"同一变量多条非阻塞赋值以最后一条为准"）。
- **产出**：7 套模型 + 7 组逐拍对照测试；权威预言机覆盖面从 5/12 提到 12/12。
- **附加价值**：每个案例对齐过程本身就是"发现设计语义细节"的素材，写进技术报告很硬。
- **风险**：SPI 的位时序此前调试耗时较长；UART/握手相对容易。

### B. 静态规则从 9 条扩到 30+ 条

- **现状**：9 条；路线图要求的 6 类未实现。
- **做法**：补齐位宽截断、未使用信号、参数边界、组合环路、CDC 风险、缺失时钟/IO 约束；每条规则配**正例与反例 RTL**（现有 `test_static_review_cases.py` 就是这个模式），并为每条规则记录来源（复用 `verification_rules/opensource_synthesis.md` 的开源工程约定）。
- **产出**：规则数达标 + 每规则可核验的案例 + 规则清单文档。
- **可核验性**：极高——规则命中与否是可枚举的，测试直接断言。
- **风险**：低。纯静态分析，不需要仿真。

### C. VCD 自动分析深化 + 接通已有失败窗口

- **现状**：解析器只有基础信息；`failure_windows` 已算未展示。
- **做法**：
  1. 把 `failure_windows` 接进 Markdown 报告与网页（这是已完成功能的补全，不是新造）；
  2. 新增上升沿/下降沿识别、信号稳定性分析；
  3. 新增**输出晚一拍/早一拍检测**——用真实缺陷验证：`uart_tx_bug_msb_first`（位序）、`spi_master_bug_extra_bit`（多发一位）、`pwm_bug_off_by_one` 都能提供确定性对照。
  4. 新增标准 RTL 与缺陷 RTL 的波形差异摘要。
- **产出**：可读的波形结论（形如"第 40 ns：输出延迟 1 个周期"）+ 用真实缺陷验证的对照。
- **可核验性**：高——结论来自 VCD 数值，不依赖模型判断。

### D. 缺陷变体横向扩展

- **现状**：老 4 案例每个 11–14 个缺陷；新 8 案例每个只有 2–3 个。
- **做法**：按路线图列的类型补：FIFO 空读/读写同拍、UART 停止位/波特率计数、SPI CPOL/CPHA、握手丢数据/重复传输、PWM 计数回绕、去抖门限边界、同步复位释放过早。目标：每案例 8–10 个，总量 100+。
- **产出**：缺陷数提升 + 每个新缺陷都有边界 testbench 覆盖与实跑证据。
- **可核验性**：高（固定矩阵逐项实跑）。
- **风险**：低，但重复度较高；需注意"不通过重复变体堆砌成果"的自我约束——每个新缺陷必须有独立缺陷原因。

### E. Yosys 综合分层证据（新解锁）

- **现状**：**Yosys 刚刚可用**——`pip install yowasp-yosys` 装好了 Yosys 0.69（WASM 版），已实测能综合我们的 RTL 并输出门级网表与单元统计。
- **做法**：新增 `synth` 证据层，报告分开显示 `simulation / synthesis / timing / bitstream / hardware`，未运行阶段明确标 `not_run`；先只做综合可行性（`read_verilog` + `synth` + `stat`）与资源统计。
- **产出**：从"只做仿真"升级为"仿真 + 综合分层证据"，显著区别于同类作品。
- **注意**：必须严守项目自定规则——综合通过不等于时序收敛或上板通过，报告里要显式分级。
- **风险**：中等。WASM 版 Yosys 速度较慢，需要控制综合的 RTL 规模与超时；不要承诺时序分析（无时序库）。

### F. 案例数从 12 提到 14+

- **做法**：补两个常用案例（候选：简单 SPI 从机、Johnson 计数器、边沿消抖组合、跨时钟域握手同步器、简易仲裁器）。
- **产出**：案例数达标，每个案例配齐 RTL/contract/spec/边界 testbench/参考模型/缺陷。
- **说明**：这类扩展必须成套做（否则又变成"有参考设计、零缺陷"的错位），单案例成本高于 D。

### G. 自定义 RTL 行为仿真对比（阶段 7 后半段）

- **做法**：让用户上传的 RTL 与标准 RTL 跑**同一份 TestPlan**，比对结构化记录与 VCD，输出差异摘要。
- **产出**：把"结构级对比"升级为"行为级对比"，是教学闭环的关键一环。
- **风险**：中等——需要把 `plan-run` 流程对自定义 RTL 打通并在网页暴露。

## 三、我的建议顺序

如果目标是"用有限时间最大化可核验成果与展示效果"：

1. **B（静态规则 9 → 30+）**：性价比最高，纯离线、可枚举验证、直接补齐路线图硬指标。
2. **C（VCD 深化 + 接通失败窗口）**：既补全已有功能，又能用真实缺陷给出确定性结论。
3. **A（参考模型对齐剩下 7 套）**：技术深度最高，且每套对齐都能挖出真实语义细节。
4. **E（Yosys 综合分层）**：展示价值高，工具刚就绪；注意分级口径。
5. **D / F（缺陷与案例横向扩展）**：量大但重复度高，适合在时间有余时做，且要控制"不堆砌"。

**不建议**现在做的：技术报告 PDF / PPT / 视频（材料类）——按你的要求先不动，但它们是提交硬门槛，留给最后集中做。

## 四、工作量估算（粗略）

| 项 | 预估规模 | 主要风险 |
|---|---|---|
| B 静态规则扩到 30+ | 21+ 条规则 × (实现 + 正反例测试) | 低 |
| C VCD 深化 | 3 个新分析能力 + 报告/网页接入 + 真实缺陷对照 | 中（VCD 边沿语义） |
| A 参考模型对齐 | 7 套 × 逐拍对照迭代 | 中高（每套语义细节不同） |
| E Yosys 分层 | 1 个证据层 + 报告分级 + 资源统计 | 中（WASM 性能） |
| D 缺陷扩展 | 10+ 新缺陷 × (RTL + tb 验证 + manifest) | 低 |
| F 案例扩展 | 2 个案例 × 成套资产 | 中 |
| G 行为对比 | plan-run 打通 + 差异摘要 | 中 |

以上均为可独立交付的增量，做完任意一项都能立刻补进实验报告与技术报告。
