# Icarus 智测成果扩展路线图

更新日期：2026-09-09

本文记录后续用于扩大项目工作量、提升技术含量和增强比赛展示效果的具体方向。所有扩展必须产生可复现的代码、测试、实验数据或文档证据，不通过重复复制文件堆砌成果。

## 一、目标规模

最终目标：

```text
14 类以上 FPGA 案例
70 个可复现 RTL 缺陷
12 套 reference model
30+ 条静态检查规则
多来源交叉验证
VCD 自动分析
2～3 个真实模型公平实验
自定义 RTL 对比和学习计划
仿真/综合分层证据
完整比赛材料
```

## 二、优先级路线

### 阶段 1：扩大缺陷基准（近期）

当前缺陷数已扩展到 70 个，覆盖 12 个案例；后续目标是继续增加协议和时序类缺陷，并保持每个缺陷可触发、可审计。

新增缺陷必须具备：

- 独立缺陷原因；
- 明确触发条件；
- 预期行为和实际行为；
- 对应 testbench 或可触发的 AI 测试；
- manifest 记录；
- 仿真证据或明确的 `inconclusive` 原因。

优先增加：

- FIFO：空读、满写、指针回绕、读写同时更新、顺序错误；
- UART：起始位、停止位、位序、busy、波特率计数错误；
- SPI：CPOL、CPHA、MOSI 位序、done 时序错误；
- 握手：ready/valid 依赖、数据保持、重复传输、丢数据；
- PWM：占空比边界、计数回绕、输出反相；
- 去抖：门限、计数清零、复位状态错误；
- 同步复位：释放过早、同步级数不足、极性错误。

验收指标：

- manifest 中缺陷数量达到 70；
- 固定矩阵逐项运行；
- 公开检出、误报和不可判定结果；
- 不可判定项不能计入缺陷检出。

### 阶段 2：Reference model 扩展（进行中）

为 FIFO、UART、SPI、握手协议、按键去抖、PWM、多路选择器和同步复位增加 Python reference model。

当前已为上述 8 类案例接入确定性模型和独立单元测试，并将其纳入 `check_plan_consistency`。模型参数已进入 DUT contract，并由 testbench 实例化覆盖和 reference model 读取：FIFO 深度/位宽、UART 每位时钟、SPI 位宽、去抖门限和 PWM 位宽均不再只依赖模型内常数。复杂协议的 CPOL/CPHA、波特率和异步 FIFO 参数仍需在后续 contract 中显式化。

每个模型至少包含：

- 状态定义；
- 输入处理；
- 输出计算；
- 复位行为；
- 边界条件；
- 单元测试；
- 与标准 RTL 的对照测试。

目标流程：

```text
AI 生成测试输入
→ reference model 计算 expected
→ 生成 testbench
→ Icarus 仿真
```

### 阶段 3：RTL 静态质量报告（已完成首版）

将规则包扩展为可执行的 RTL 审查器，输出 JSON 和 Markdown 报告。

当前已提供 `src/iverilog_ai/core/static_review.py` 和 `scripts/review_rtl.py`：支持规则 ID、严重级别、行号、证据片段、修复建议、源码 SHA-256、质量评分和免责声明；网页可对内置或自定义 RTL 执行审查并下载 JSON/Markdown。当前规则为保守的教学/triage 检查，不宣称综合或时序签核。

检查内容：

- 时序逻辑阻塞赋值；
- 组合逻辑非阻塞赋值；
- 缺少 default；
- 不完整敏感列表；
- 异步复位释放风险；
- 多驱动信号；
- 组合环路；
- CDC 风险；
- 位宽截断；
- 未使用信号；
- 参数边界；
- 缺失时钟和 IO 约束。

网页显示：

- 严重问题；
- 警告；
- 建议；
- 代码质量评分；
- 对应规则来源和修复方向。

### 阶段 4：VCD 自动波形分析（已完成首版）

在现有 VCD 生成和 GTKWave 启动能力上增加：

当前已提供无第三方依赖的 `vcd.py` 解析器：读取 timescale、层级信号、位宽、时间范围、变化次数和受限变化记录；流水线会把分析结果写入 `simulation.config.vcd_analysis`，Markdown 报告显示波形摘要，网页支持信号列表、时间窗口分析和 JSON 下载。GTKWave 仍保留为可选人工复核工具。

- 信号列表；
- 时间范围选择；
- 失败周期窗口；
- 上升沿/下降沿识别；
- 输出晚一拍或提前一拍检测；
- valid/ready 稳定性分析；
- 标准 RTL 与自定义 RTL 波形差异。

输出示例：

```text
第 40 ns：输出延迟 1 个周期
第 70 ns：valid 保持不稳定
第 90 ns：复位释放过早
```

### 阶段 5：多来源交叉验证

逐步引入以下证据源：

- Icarus/vvp；
- Python reference model；
- 结构化断言；
- 规则推导结果；
- 第二套独立 reference model；
- 自定义 RTL 与标准 RTL 行为对比；
- 多次模型输出一致性。

结论分级：

```text
verified：仿真、参考模型和关键断言一致
passed_unverified：只有仿真通过，没有独立预言机
plan_inconsistent：AI expected 与独立来源冲突
assertion_failed：关键结构化断言失败
inconclusive：证据不足或工具未完成
```

### 阶段 6：真实模型公平实验

至少选择 2～3 个真实模型，每个模型执行至少 10 次重复实验。

所有模型使用相同：

- 案例集合；
- 缺陷集合；
- 测试向量预算；
- 仿真超时；
- contract 和规则包；
- 结果统计口径。

统计指标：

- TestPlan 请求级合法率；
- reference model 一致率；
- 参考 RTL 误报率；
- 缺陷检出率；
- 首次发现时间；
- 平均生成延迟；
- 超时率；
- token 使用量；
- 费用估算；
- 标准差和失败率。

必须同时公开成功、失败、未检出和不可判定请求。

### 阶段 7：自定义 RTL 教学闭环

形成完整流程：

```text
上传 RTL
→ 提取 module/端口/时钟/复位
→ 选择标准 RTL
→ 静态结构对比
→ 同一 TestPlan 行为仿真
→ VCD 波形对比
→ AI 解释差异
→ 生成学习计划
```

学习计划至少覆盖：

1. 端口、位宽和 contract；
2. 时序逻辑和非阻塞赋值；
3. 状态机和边界条件；
4. FIFO、握手和 CDC；
5. 结构化断言和形式验证。

### 阶段 8：综合和比赛材料

可选接入 Yosys，报告分开显示：

```text
simulation
synthesis
timing
bitstream
hardware
```

未运行阶段必须标记 `not_run` 或 `inconclusive`。

同时完成：

- 技术方案 PDF；
- 答辩 PPT；
- 3～5 分钟演示视频；
- 系统总览图；
- 正确案例证据包；
- 缺陷检出证据包；
- 模型对比报告；
- API 和安全设计说明；
- 开源贡献文件。

## 三、成果展示口径

不只展示：

```text
缺陷检出率
```

还要同时展示：

```text
TestPlan 合法率
参考模型一致率
参考 RTL 误报率
有效计划缺陷检出率
不可判定率
平均延迟
费用估算
```

禁止把：

- AI 自评当作正确性证据；
- Icarus 仿真通过宣传为综合或上板通过；
- 重复缺陷变体宣传为独立技术成果；
- 未完成实验写成已完成。

## 四、当前基线

- 缺陷基准：70 个（12 个案例），固定矩阵最近一次实跑 70/70 检出、参考误报 0、不可判定 0；
- 常用 FPGA 案例：已加入 FIFO、UART、SPI、握手、去抖、PWM、多路选择器、同步复位等；
- 规则包：已支持通用规则、案例规则、开源规则来源说明和规则哈希；
- 结构化断言：已支持五种受控模板；
- 证据包：已支持目录、SHA-256 清单和 ZIP 下载；
- 自动化测试：当前 98 个测试通过；
- 下一项优先任务：缺陷基准扩展、reference model 扩展和 VCD 自动分析。
