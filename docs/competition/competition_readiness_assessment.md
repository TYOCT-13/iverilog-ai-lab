## 一、合规性逐条评估

### 1. 赛道方向匹配度：强

官方规则原文对照：

> （二）**AI开发工具与开源协作**：面向代码开发、**测试**、文档、数据处理、知识管理、项目管理和开源社区协作等环节，形成提升效率或质量的智能工具、扩展组件和自动化流程。作品可以聚焦代码理解与辅助、**自动化测试**、文档生成与翻译……

Icarus 智测正是一个"自动化测试"方向的智能工具，并且：

- 上游是真实开源项目（Icarus Verilog），项目**不修改、不复制**其源码，以扩展形式存在 —— 同时命中第（三）方向"插件开发、测试用例、教程文档"；
- 产出包含代码仓库、pytest 测试套件、CI 工作流、验证规则包、可复用 `TestPlan` Schema、缺陷基准集 —— 满足规则第（六）条"至少形成一种可复用或可验证的开放成果"。

### 2. 最容易踩的一条红线：规则第三条第（二）款

> 仅使用通用开源软件作为普通开发环境，**不等同于"AI+开源"融合创新**。

这一条淘汰的是"用 Python + pip 写了个 AI 应用"这类作品。本项目不在此列，理由是结构性的而非话术性的：

- **AI 处在关键路径上**：自然语言验证目标 → 受 Schema 约束的 `TestPlan` → 确定性生成 testbench。没有 AI 这一层，用户就得手写测试向量；
- **同时明确限制 AI 的权限**：模型不能输出 Verilog/命令/SVA，期望值有独立参考模型复算，结论只由本地 `iverilog`/`vvp` 裁决。这是针对"AI 测试预言机幻觉"的**具体设计**，正好回应规则"AI 作用明确、必要"的加分口径；
- **开源是实质依赖而非环境**：Icarus 是裁决引擎，生态贡献（缺陷基准、中文案例、规则包）是产出物。

### 3. 明确不计分的项，本项目也没踩

规则写明"不以模型参数规模、算力投入、代码行数、材料数量或开发成本作为评分依据"。项目文档里没有任何地方宣称这些，方向是对的。

## 三、必须正视的三个技术风险

这三条直接压在**分值最高的 25 分项**上，评委只要追问就会暴露。

### 风险 1：在线实验数字目前自相矛盾（最要紧）

在线模型实验（200 次请求）的汇总里，**参考误报 25/40**。逐条核查后确认，这 25 条全部是 `severity="warn"` 的期望值不匹配，根因是 AI 写的 test plan 期望值有偏差（多周期向量只写终值、复位/时序建模错误），**不是 RTL 有缺陷**。

更要紧的是：`core/executor.py:276` 把 warn 级反例一律判为 `PASSED_WARNINGS`，而缺陷检出统计按"存在结构化失败反例"计数。**所以 `16/16 检出` 和 `25/40 误报` 是同一把尺子量出来的两个数** —— AI 猜错期望值既会"检出缺陷"，也会"误报参考设计"。目前没有证据说明这 16 个检出都对应 manifest 里写的真实缺陷行为。

如果评委追问一句"你的 AI 到底是在测缺陷还是在测它自己猜错期望值"，现在答不上来。**这件事必须在提交前修掉**，改法也不难：项目已有 `reference_model.py`，让参考模型复算的 expected 成为权威预言机，AI 的 expected 偏差单列成"AI 期望值准确率"指标。

修完之后故事反而更强：**"我们不是让 AI 判对错，而是让 AI 只生成测试意图，正确性由独立参考模型和 Icarus 共同裁决"** —— 这正是 25 分项想看的"可验证效果"。

### 风险 2：固定矩阵 50/50 的说服力边界

50 个缺陷全部由本项目的自研 testbench 检出，属于"**自己出题自己判卷**"。它能证明工具链完整，但不能证明"AI 比基线强"。真正有说服力的是**同预算下 fixed / random / AI 三个策略的对比**，而这个对比目前还是 16 缺陷基线的旧数据（fixed 100%、random 81.25%、Mock AI 81.25%），且被文档模糊化处理过。

建议：在 50 缺陷基线上重跑三策略对比（离线可复现，成本为零），并把 AI 策略**未检出的那部分缺陷公开列出**。规则与项目自定规则都要求"不得只展示最好结果"，主动公开反而是加分动作。

### 风险 3：开发者工具在评委视角下的天然劣势

本赛道的多数作品会是"视觉/文本效果好演示"的 AI 应用（去年参考的国二作品 `apuomline/DL-ICG` 就是细粒度识别）。RTL 验证的难度**不在评委的直观认知范围内**：评委看不到"漂亮结果"，看到的是 JSON、日志和波形。

对策是**把不可见的难度变成可见的证据**：
- 用一张图说清"AI 测试生成为什么不可信"（期望值幻觉的具体反例，你已经有一堆真实数据）；
- 演示序列按"人的痛点"走：写测试 → AI 生成计划 → Icarus 裁决 → 缺陷检出失败反例 → VCD 波形 → 报告；
- 明确"仿真通过 ≠ 综合/时序/上板通过"，这种克制在工程评审里是专业信号。

## 四、与 2025 年获奖作品的横向对比

我核查了会话里调研过的获奖仓库 `apuomline/DL-ICG`（网络监督细粒度识别赛道，2025 年获奖），用 GitHub API 拉了它的**完整文件树**：

| 对比项 | DL-ICG（2025 获奖作品） | Icarus 智测（本项目） |
|---|---|---|
| 文件构成 | 4 个 csv 数据清单 + 5 个 yaml 配置 + 4 个 py 脚本 + Dockerfile + 3 个 shell + requirements | 22 个核心模块 + 64 个 RTL + 50 个缺陷变体 + 24 个测试文件 + 16 份规则 + UI + CI |
| README 体量 | **490 字节** | 4.7 KB 且结构完整 |
| 许可证文件 | 无 | Apache-2.0 |
| 测试 / CI | 无 | pytest + GitHub Actions |
| 中文文档 | 无 | docs/ 12 份 + spec/ 7 份 + examples/ 15 份 |
| 协作痕迹 | 单人 | 同样单人（**不是加分项，也不必伪造**） |

**判断**：去年获奖作品的技术叙事是"赛题排行榜成绩 + 一套能复现的训练/推理脚本"，**开源工程规范几乎为零**；而 Icarus 智测在工程完整度、文档、测试、可复现性上明显更重，且是**面向开源生态的工具类作品**（更贴本届"AI+开源"的立意）。

但要客观说明两点：
1. 两者不在同一赛道，DL-ICG 是算法挑战赛（有客观排行榜名次背书），本项目是开放式主题赛（**主观评审**）——所以"工程更重"不等于"分更高"；
2. 我**没有**拿到任何关于本届"AI+开源"赛道报名规模的一手数据。这是一个 2026 年新设赛道，竞争密度无法精确预测。

## 五、获奖预测与推导过程

### 赛制与概率结构（官方原文）

> 复赛设一、二、三等奖。**以晋级复赛的有效作品数量为基数**，获奖作品数量分别按照不超过 **15%、25%、30%** 的比例取整计算，复赛一、二等奖获奖团队晋级全国总决赛。

关键推论：**省奖的分母是"通过初赛形式审查的有效作品"，而不是全部报名队**。也就是说：

- 只要材料完整、合规、通过形式审查进入复赛 → 自动进入"前 70% 有奖"的池子；
- **材料缺失 = 连分母都进不去**，这是当前唯一会让项目"零收获"的路径；
- 初赛是形式审查（材料完整性、主题符合性、原创性声明、开源披露、合规），不是技术打分 —— **作品再强也不能豁免材料要求**。

### 逐档概率判断

| 档位 | 概率 | 推导 |
|---|---:|---|
| **省二等奖（前 15%–40%）** | **约 45%** | 基准情形。作品技术体量与完整度足以在复赛池中处于中上，但 25 分项的效果数据目前不可用、技术报告尚未撰写，很难稳定冲进前 15% |
| **省一等奖（前 15%）** | **约 30%** | 需要三件事同时成立：① 在线实验口径修好并重跑出干净数字；② 15 页技术报告写得专业（用户自己引用的判断是"花 60% 精力打磨技术报告"）；③ 3–5 分钟视频把不可见的难度讲清楚。三者都做到，冲前 15% 是有机会的 |
| **省三等奖（前 40%–70%）** | **约 20%** | 情形：材料踩线补齐，但技术报告平铺直叙、效果数据仍是旧口径，评委感受到"工程不少、亮点没讲透" |
| **无缘奖项** | **约 5%** | 仅当材料未补齐、出现学校/指导教师信息、或《开源及第三方资源使用清单》不合规导致形式审查不通过 |
| **国赛奖项** | 拿到省二以上后才有资格；国赛为线下答辩，15%/25%/30% 同样比例。**进入国赛后再获奖概率较高（约 70%+）**，因为国赛池本身已过滤过一轮 | — |

**综合判断：省二以上（含晋级国赛）的概率约 75%；其中省一约 30%。**

这是估计而非承诺。它的核心假设是：**材料在 10 月 15 日前补齐，且技术报告质量达到及格线以上。** 如果只交代码不交材料，以上概率全部归零。

### 与"最低成本拿省二"目标的匹配度

你的目标是"用最低的成本拿到省二以上"。就成本结构而言，这个项目是**很好的选择**：

- 无算力成本（Icarus + Python，本地跑）；
- 无数据获取成本（RTL 与缺陷集自己可控）；
- 唯一的现金支出是 500 元参赛费；
- 已投入的工程资产**不需要重做**，剩下的是材料工作。

反过来，最大的成本风险是**时间**：35 天要完成"修实验口径 + 重跑实验 + 技术报告 + 视频 + PPT + 开源清单 + git 发布"。这个量对一个 1–3 人团队是紧但可行的，**前提是不要再往工程里加新功能**。

## 六、按"能不能拿分"排序的行动清单

### P0：不做就一定掉档（约 10 天）

1. **修在线实验口径**：内置案例改用参考模型复算 expected，AI 期望值偏差单列指标；重跑 14 案例 × ≥10 次；公开未检出缺陷与失败请求。
2. **在 50 缺陷基线上重跑三策略对比**（fixed / random / Mock AI），这是零成本、可复现的硬数据。
3. **写《开源及第三方资源使用清单》**：核验 Icarus Verilog（GPL-2.0-or-later）、Python（PSF）、pydantic（MIT）、streamlit（Apache-2.0）的实际版本与许可证，写清自研边界、关键许可义务、开放方式。**这是形式审查项，缺了直接出局。**
4. **git 首次提交 + 推送公开托管平台**：规则要求"评审期内持续有效的访问链接"。当前 `main` 分支零提交。
5. **给 README 那处不实表述降级**（"失败周期波形摘要已完成"实际未接入报告与网页）。评审逐条核对时，不实表述是诚信问题，代价远大于收益。

### P1：决定省二还是省一（约 15 天）

6. **技术报告 PDF**（≤15 页，按官方附件 2《技术报告参考大纲》）：
   - 必须包含**"人工智能工具使用说明"**章节（规则第三条第（七）款强制），说明 AI 在哪些环节参与了开发、你如何审核验证；
   - 必须包含需求与场景论证（15 分项）、创新点对比（20 分项）、AI 与开源融合方式与许可证义务（20 分项）、实验对比表与效果数据（25 分项）；
   - 反复自查：**不得出现学校名称、校徽、指导教师信息**。
7. **3–5 分钟演示视频（MP4）**：按"用户痛点 → AI 生成计划 → Icarus 裁决 → 缺陷检出 → 报告/VCD"的真实操作录制，不要只放 PPT。
8. **补齐开源社区文件**：CONTRIBUTING / SECURITY / CHANGELOG / Issue 模板 / PR 模板（15 分项"维护机制"）。
9. **作品名称（≤20 字）+ 300 字简介**（按"问题—方案—实现—效果—开放成果"组织）。

### P2：有余力再加（约 5 天）

10. 8 个新案例（FIFO/UART/SPI/握手/去抖/PWM/mux4/同步复位）补缺陷变体 —— 让"14 案例"和"缺陷基准"覆盖一致，避免"案例多但基准只覆盖 4 个"的展示短板。
11. 可选：Yosys 综合分层证据（`simulation / synthesis / timing / bitstream / hardware` 分开报告，未运行标 `not_run`）—— 能显著区别于纯仿真项目，但要严格控制时间。
12. 答辩 PPT（晋级国赛后提交）。
