# 从真人试用原片到提交视频

先保存完整事实，再做展示版本。建议把文件分为三类：真人试用原片、独立审核原始记录、团队演示成片。三者可以相互引用，但不能互相冒充。

## 1. 要准备哪两种录屏

| 内容 | 谁操作 | 用来证明什么 | 应怎样保留 |
|---|---|---|---|
| 真人试用原片 | 实际试用者，主持人只按任务卡提示 | 操作是否能完成、哪里卡住、如何理解结果 | 连续原片、任务起止时间、提示和错误原样保留 |
| 项目演示片 | 熟悉工具的团队成员 | 完整展示真实功能与证据链 | 先保存连续录制母版，再剪成 3–5 分钟版本 |

独立审核主要依据逐条技术记录、源码与运行产物；可以录屏辅助，但视频不能代替 [审核记录](../review/README.md)。试用者数量及另请技术审核人的安排是项目强化证据的建议，不是此处声称的竞赛强制人数或第三方认证要求。

依本项目现有官方附件存档的当前记录，展示视频为 **3–5 分钟 MP4、文件不超过 300 MB，并满足匿名性要求**。提交前以当届[官方通知与附件](https://www.aicomp.cn/notice/notice-3/4890.html)及报名系统为准；本文件的录制分镜、分辨率和受试者安排不是官方附加规定。

## 2. 真人试用怎么录

1. 使用 [试用任务卡](../trial/task_card.md)，提前确认对方愿意参加。分别确认是否允许录屏、录声音、内部留存、匿名引用反馈及公开视频；不把参加试用视为默认允许公开身份。
2. 给试用者代号。先记录环境、经验、项目版本和开始时间。录屏不必开摄像头，也不要求显示真实姓名；关闭通知、聊天窗口、账户页和凭据管理器。
3. 开始录制后，让试用者独立读任务并操作。主持人不提前指出正确按钮；必须帮助时记录时间、原话和帮助内容。不能因试用者失败而把他排除出统计。
4. 任务结束时让对方用自己的话解释结果，填写 [试用者反馈单](../trial/forms/participant_feedback.md)或同目录的 Word 版；组织者再按 [v2 会话模板](../trial/forms/session_feedback_template.json)转录。不要诱导其给“很方便”“完全正确”等评价。
5. 保存原片，记录文件名、时长、SHA-256 和任务时间点；断录、崩溃和重试另开文件，并标注接续关系。公开版本可遮盖隐私，但保留经同意的原始版本供内部核对。

不必把 30–40 分钟试用硬剪成竞赛的 3–5 分钟演示。试用记录用于反馈证据，最终演示由团队另录。引用试用者原话或片段前，请其核对选取的上下文及公开范围。

## 3. 团队演示的准备顺序

建议用 1920×1080、30 fps 录制，也可选 1440×900 等清楚呈现界面的尺寸；这是清晰度建议。浏览器缩放保持文字能读，鼠标移动缓慢，避免桌面和手机录屏来回切换打断操作。

使用系统已有录屏工具或现有录制软件即可，不需要购买新服务。正式录之前做 20 秒测试：确认录到的是目标窗口、点击位置清楚、麦克风能听见、界面正文可读。

在仓库根目录启动：

```powershell
./start_ui.ps1 -Port 8600
```

打开启动器显示的地址。先到「工具设置」→「测试计划与模型」选「离线模式」，然后按 [约 4 分 30 秒分镜](demo_script.md)彩排：

1. 简单 ALU：生成计划、运行计划、看实际比对与期望值来源。
2. 导出证据 ZIP，检查是否包含刚才的 run ID 和真实工件。
3. 两份 RTL 对比：`simple_alu.v` 对已有的 `simple_alu_bug_xor.v`，查看真实差异并下载报告。
4. 解释有限激励、自动接口草稿、编译失败和不可判定的边界。

先确认这些步骤在当前版本能完成，再开始正式录制。彩排遇到错误先修正或明确记录，不依靠字幕把实际失败改成成功。

## 4. 在线片段只在需要时执行

离线规则规划器、本地 debug HTTP 服务都不是大模型。常规离线演示不需要密钥；网页「在线模型」按钮与命令行小样本入口也不是相同的请求预算，不能混用它们的预算承诺。

若确需在线片段，先按 [接入指南](../experiment/api_handoff.md)在录制画面外配置 endpoint、model 和密钥环境变量。下面默认不联网，例中密钥已由本机环境注入 `IVERILOG_AI_API_KEY`：

```powershell
python -X utf8 scripts/check_online_api.py --dry-run --cases simple_alu --repeats 1 --max-requests 1 --max-output-tokens 2048 --simulate
```

检查预检的 `missing`、服务和模型配置。只有操作者决定产生真实调用后，才把 `--dry-run` 改成 `--execute` 执行同一组参数：

```powershell
python -X utf8 scripts/check_online_api.py --execute --cases simple_alu --repeats 1 --max-requests 1 --max-output-tokens 2048 --simulate
```

这一条可能收费；请求次数与输出 token 限制不是金额硬上限，输入也可能计费。失败也耗一次尝试，入口不自动重试或降级。不要展示密钥设置命令，不要为录制“好看”循环重试而不记录消耗。保存新输出目录里的 `api_check.json`、计划和仿真工件，画面标明“真实在线接入，当次配置验证”，失败则如实说明。

如果没有执行在线步骤，成片仍可完整展示离线工作流，但不能用服务商名称或生成动画暗示已经调用真实模型。

## 5. 剪辑与发布检查

允许裁掉无关桌面、口误和长等待；等待压缩要明确标注“等待已缩短”或实际倍速。每个运行片段保留输入、点击、状态反馈和对应结果的关联。另一次重试可以作为新片段展示，但须说明重试原因，不能拼成第一次就成功。

字幕区分“本次运行”“历史实验”“真人反馈”。演示已有人工变体时写清是已知错误样例；展示 `identical` 时写清是有限激励内一致，不能改成“已证明等价”。不要用红框、字幕或后期图层伪造网页不存在的判定。

导出 MP4 后从头播放一次：检查时长、音量、文字、结论和 run ID，确认没有个人资料、学校/团队身份等不符合当届匿名要求的画面。不要为了匿名去除第三方必须保留的许可或出处；必要时将这些内容保留在相应佐证材料中，并依官方规则处理视频画面。

文件检查示例（改成真实成片路径）：

```powershell
Get-Item ./demo-final.mp4 | Select-Object Name, Length
Get-FileHash ./demo-final.mp4 -Algorithm SHA256
```

文件大小留余量，建议明显低于 300 MB；若超过限制，调整编码压缩或码率后再次检查正文可读性，不凭文件名判断 MP4 合规。保留母版、成片、字幕稿、剪辑说明及对应证据包。对外发布真人姓名、原话、原始录像或声音前再次核对其授权范围；未获授权就不放入公开视频。
