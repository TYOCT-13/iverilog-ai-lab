# 3–5 分钟网页演示脚本

这是一份准备执行的脚本，不是已完成演示记录。建议录成约 4 分 30 秒；实际按当届提交要求调整。先做一次完整彩排并保存原始录像，再剪出提交版，具体方法见 [录屏工作流](recording_workflow.md)。

本片演示 **Icarus 智测** 的真实离线路径：规则规划器生成计划、参考模型提供判据、Icarus 仿真、结果导出。离线规划器和本地调试服务都不是真实 LLM；不要把离线片段配成“DeepSeek 现场生成”。

## 开拍前

在仓库根目录执行 `./start_ui.ps1 -Port 8600`，使用启动器打印的实际地址；当前常用地址为 `http://127.0.0.1:8600/`。网页已有实例时先确认打开的是本项目，避免启动第二套后录错窗口。

准备现有 `rtl/simple_alu.v` 和 `rtl/simple_alu_bug_xor.v`，不要临场新造 RTL。关闭通知和含身份、密钥的窗口。先到「工具设置」→「测试计划与模型」→「生成方式」选「离线模式」，确认 Icarus 可用。

| 0:25–1:05 | 「验证一份 RTL」→「案例」选择「简单 ALU」；填写或展示「验证目标」；点击「生成测试计划」 | “计划需符合接口约束，生成完成后才允许执行。这里展示真实生成的输入序列。” 不预报固定向量数量，以本次输出为准。 |

如准备使用交通灯做成功段，将案例替换为「交通灯·紧急模式」，仍使用「生成测试计划」「运行测试计划」两个当前按钮。不要再使用旧脚本的“执行真实 Icarus 仿真”“生成本次运行证据包”，也不要展示不存在的“即将加入”占位案例。

## 真实结果与剪辑

- 先录下完整操作、等待和结果，保留原片；提交版可删去长等待，并标注“等待片段已缩短”或倍速。
- 不把不同 run 的按钮、结果和报告拼成同一次成功；不隐藏错误后用另一次的成功画面冒充原结果。
- 字幕中的测试数、耗时和模型来源跟随本次记录。历史统计另标日期、数据集和来源，不叠到现场结果上冒充新实验。
- 宣传演示与真人试用录屏分开保存。试用者遇到的卡点和失败是研究记录，不为了成片好看要求其重演成“首次顺利使用”。

## 可选：真实在线模型短片段

只有确需展示真实在线接入时才追加，且保留服务来源与实际请求记录。优先按 [API 接入指南](../experiment/api_handoff.md)使用有预算的 `scripts/check_online_api.py`，先 `--dry-run`，再由操作者决定是否显式 `--execute`。录屏前配置凭据，画面不显示密钥。

离线与在线片段分章标识；一次真实接入成功只证明该配置当次可用，不能替代多轮公平实验。没有做在线调用就直接保留整片离线说明，不加虚构的在线画面。
