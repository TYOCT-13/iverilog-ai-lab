# T06｜阅读规则审查与建议

标签：RTL 开发者 / 教学 / 规则可理解性。状态：**任务方案，尚无真人执行记录**。

## 参与者任务

**目标**：根据工具的规则检查，决定自己下一步是否需要检查某段代码，并解释理由。

**前提**：在工作台已选择一个内置案例，或已上传组织者给出的 RTL。基础任务采用“离线模式”，不发送源码到在线服务。

**时间盒**：8–10 分钟。

**步骤**：

1. 记下当前案例或文件名，进入“规则审查”，点击“检查代码”。
2. 查看“参考评分”“检查状态”“问题数量”。用自己的话说明三者分别告诉了你什么。
3. 若有问题表，选一条你愿意进一步核对的项目，查看规则 ID、行号、说明和代码片段；如果没有项目，记录实际页面。
4. 查看“规则与出处”，尝试找到刚才那条规则的依据。
5. 仍使用离线模式，点击“生成修复建议”。比较建议与原规则结果，指出哪条有用、哪条不清楚或你不同意；允许没有意见。
6. 使用“导出审查报告”下载 Markdown 或 JSON。写下仅凭这份报告，你愿意确认什么、还不愿意确认什么。

**观察与证据**：审查结果截图、选中规则的 ID 与自己的解释、导出报告、建议前后评分记录。不要为了给反馈而编造一条问题。

**终止与支持条件**：无法定位代码或规则超过 3 分钟可求助。若意外处于在线模式，先回工具设置改为离线；不点击在线建议来完成本卡。不要将建议直接写回源代码。
