# T04｜上传 RTL 并确认接口

标签：RTL 开发者 / 自定义输入 / 接口校验。状态：**任务方案，尚无真人执行记录**。

## 参与者任务

**目标**：让工具接受一份你能理解的 RTL，并确认测试使用的是你认可的端口、时钟与复位信息。

**前提**：有基础 Verilog 经验；网页与 Icarus 可用。基础任务使用 `rtl/mod10_counter.v` 的独立副本及其规格。自有 RTL 是可选扩展，须有使用权限，不含第三方秘密。基础任务不联网。

**时间盒**：12–15 分钟。

**步骤**：

1. 进入“验证一份 RTL → 工作台”，在“案例”选择“自定义 RTL”，用“上传 RTL 文件”上传副本。
2. 查看自动提取的接口草稿。若确实上传了多个模块，使用出现的“顶层模块”选项；只有一个模块时不要求寻找此控件。
3. 在“端口与时钟”核对端口方向、位宽、时钟信号与周期、复位有效电平和复位持续周期。对照文件或规格，记录哪项最难确认。
4. 点击“从表格生成 JSON”，查看“接口定义 JSON”。**直接在这个 JSON 文本框中把 `clock.period_ns` 改为 `20`**，再点击“用 JSON 刷新表格”，观察表格中的时钟周期是否对应这次编辑。此步不再修改表格；记录你如何理解两种编辑方式的关系。
5. 点击“校验接口”；看过提示后才生成并运行离线测试计划。记下运行结果与期望值来源。
6. 如有需要，使用“导出 → 接口定义 JSON”保存接口。将本次 RTL 副本、接口文件与报告一起交回。

**观察与证据**：保存上传成功或失败提示、修改前后接口、校验结果及报告。记录自己做了什么、自动草稿哪些内容需要人工判断；不以“校验通过”代替行为正确性判断。时钟周期编辑以确认后的接口为依据，不要求根据计划里的同名字段推断真实仿真周期。

**终止与支持条件**：不清楚时钟/复位语义时停止填写并求助，不猜值。每个上传文件上限为 2 MB；超限或格式不支持时记录提示，不裁剪真实工程。基础任务完成后才尝试自有 RTL；多时钟、厂商 IP 或外部 include 问题可作为范围限制记录。
