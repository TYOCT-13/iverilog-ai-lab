# T08｜把一次结果交给别人查看

标签：核心流程 / 证据导出 / 复核交接。状态：**任务方案，尚无真人执行记录**。

## 参与者任务

**目标**：把刚才的一次测试交给不在场的人，让对方能够定位输入、结果及支持它的证据。

**前提**：已用“生成测试计划 → 运行测试计划”得到一次结果；仅“运行示例测试”没有本卡全部导出项。准备一个属于本次试用的下载目录。

**时间盒**：8–10 分钟；独立重跑另按 T09 安排。

**步骤**：

1. 在“工作台 → 测试结果 → 结论 → 运行详情”记录本次运行 ID、案例或上传文件名。
2. 进入“运行档案”，展开“最近运行”，寻找刚才那次记录。记下你用什么信息对应；若没有找到，记录当前列表和原因。此页不要求寻找重跑按钮。
3. 回工作台，进入“导出证据”，下载“Markdown 报告”和“测试计划”；查看“文件位置”及“生成的 testbench”。
4. 点击“打包本次结果”，再点击“下载证据包 ZIP”。保存到本次下载目录，不覆盖前一次证据。
5. 解压 ZIP，打开包内 README 与清单。根据实际内容，写一段简短交接说明：这次测了谁、结果在哪里、如何找到一条依据、你认为还需要哪些文件。
6. 切换到另一个案例后，观察能否误下载上一轮证据。不要删除先前下载的文件，它们仍属于原来的运行。

**观察与证据**：ZIP、下载报告、计划、当前 RTL 副本的来源和 SHA-256（不会计算可请组织者协助）、运行 ID及交接说明。实际包缺某文件就记录缺项，不自行补写成“已包含”。

**终止与支持条件**：打包失败保留错误与运行 ID；下载后找不到文件先记录再求助。不能仅凭 ZIP 能解压就声称可复现；如果对方拿不到原输入，先停止“已能独立重跑”的判断。

## 任务记录

填 `completed`、`partial`、`blocked` 或 `skipped`，另记 `prompt_count` 与 `assistance`。导出成功、哈希核对、独立重跑是三件不同的事，实际做了哪件就记录哪件。
