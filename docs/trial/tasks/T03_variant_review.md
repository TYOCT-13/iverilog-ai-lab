# T03｜检查另一个实现版本

标签：结果阅读 / 证据定位。状态：**任务方案，尚无真人执行记录**。

## 参与者任务

**目标**：检查组织者提供的另一份实现，判断本次结果能支持怎样的结论，并指出一条依据。

**前提**：已完成 T02；有 RTL 基础者自行操作，没有基础者由组织者仅代做上传和接口准备，并记录为准备协助。使用组织者提供的 `candidate.v` 与接口定义；不修改仓库原文件。不需要 API。

**时间盒**：10 分钟；不要求修复代码。

**步骤**：

1. 在“验证一份 RTL → 工作台”，选择“自定义 RTL”，使用“上传 RTL 文件”选择本任务的文件。
2. 确认组织者提供的接口定义，点击“校验接口”。若从 JSON 导入，使用“接口定义 JSON → 用 JSON 刷新表格”，再校验；不理解接口者可以让组织者准备到这里。
3. 确认“工具设置”采用“离线模式”，回到工作台，点击“生成测试计划 → 运行测试计划”。
4. 看“测试结果 → 结论”。记录你看到的运行状态与设计结果，说明它们是否表达同一件事。
5. 查看“修复建议”。如果出现“失败记录”或“解释失败原因”，可以打开并选择一条你能理解的记录，指出信号、测试位置或期望/实际差异；没有时记录页面实际说明。也可以明确写“没找到”或“不理解”。
6. 保存 Markdown 报告。告诉组织者：你下一步会检查哪里；这份证据还缺什么。不要依据任务名称猜结论。

**观察与证据**：至少一张结果截图、一条实际反例或原始错误提示、下载的报告；记录是否把工具正常运行误读为设计正确，以及得到提示前后的表述。不是每个人都必须读懂波形。

**终止与支持条件**：接口无法校验或没有产生可用运行结果时，记录为受阻，不用作者预期补答案。查找证据超过 3 分钟可求助。不要调用在线修复、不把建议自动写回 RTL。
