# T05｜比较两份 RTL

标签：RTL 开发者 / 版本对比 / 结论理解。状态：**任务方案，尚无真人执行记录**。

## 参与者任务

**目标**：对照一个基线检查三份候选文件，分别说明工具给了什么结论、你是否有足够依据接受它。

**前提**：Icarus 可用；组织者提供 `baseline.v` 和三份中性编号的候选文件，记录发放顺序。所有输入在试用副本目录内，不能覆盖仓库源文件。不需要 API；每次仅上传当前候选。

**时间盒**：12–15 分钟；新手可只做组织者指定的一份，其他份标为未分配。

**步骤**：

1. 选择“对比两份 RTL → 工作台”。在“基线 RTL”选择“上传基线 RTL”，用“上传原版本 RTL”上传 `baseline.v`。
2. 在“候选 RTL”上传组织者指定的第一个编号文件，点击“开始对比”。
3. 记录结论、可比检查项、逐拍波形状态与接口信息。若有差异或警告，挑一条查看；若没有结果，记录实际提示。
4. 下载“对比报告”；展开“原始结果 JSON”，记下本次候选文件编号与产物位置。
5. 移除当前候选，再上传第二、第三份，逐份重复。每次运行前先观察旧结果是否仍在；不要把上一份报告当作下一份的结论。
6. 用自己的话比较三个结果：哪些足以说明当前测试下两份设计的关系，哪些还需要补充验证？不要按编号推测答案。

**观察与证据**：每份候选一条实际结论和对应报告/错误截图；保留文件编号、运行时间、可比检查项数、原话与求助记录。任务编号可相同，候选编号必须分开。

**终止与支持条件**：提示模块名或接口无法匹配时先保留提示，不自行改名“让它通过”。单次等待超过 2 分钟或一份失败后，记录并继续下一份，不要求修复文件。缺少任务文件时直接联系组织者，不临时换成其他文件。

## 任务记录

按实际情况填 `completed`、`partial`、`blocked` 或 `skipped`；部分候选没做完时说明具体编号。同一会话只填一条 T05 任务记录，在客观结果与证据中分列候选编号。另填 `prompt_count` 与 `assistance`。工具没有取得结论，也可能是完成了一次有效的试用观察；不能直接计作参与者操作失败。
