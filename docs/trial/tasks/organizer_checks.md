# 任务准备与组织者检查

**仅供组织者和独立复核者。不要把本文件、样例映射或期望结论发给参与者。**

状态：方案就绪；尚无真人试用或独立审核完成记录。代码检查、团队预演、参与者操作与外部独立复核分别留档。
参与者只执行其被分配的任务卡及中性编号文件；标准参与者包可包含其他未分配任务卡，须在入口表明确本次范围。原始输入在个人试用副本中操作，不修改仓库原 RTL。

## 统一准备

1. 固定本轮提交号、分发包 SHA-256、系统、Python/Icarus 版本、可选依赖和浏览器；记录工作区是否有修改。
2. 用本轮版本预演所选任务，另存组织者预检记录。任务样例失效时先修任务材料或标记不可执行，不能让参与者背答案。
3. 给参与者分配任务与分支，按发放顺序计时。只给中性操作提示；说明性帮助要计入 `prompt_count` 与 `assistance`。
4. 任务记录采用 `completed / partial / blocked / skipped`。`completed` 表示任务活动做完，不等于设计通过，也不等于独立完成；完成率与帮助量分开统计。同一会话每个任务 ID 只写一条记录，分支与候选编号写进客观结果、原因和证据，不重复 task_id。未分配任务不进入该参与者分母；已分配但没记录由汇总标 `missing_record`，不能替参与者填结果。
5. 下列“检查点”是组织者核实工具和材料的依据，不是参与者应当表达的意见。保留参与者原话，再另记组织者判断与证据。

## T01｜安装

- 分开记录首次安装、已有环境安装和预装打开；任务墙钟总耗时包含操作、等待与求助，额外注明下载等待，不从总耗时扣除，不引用作者历史安装秒数。
- 核心仿真需要 `iverilog` 和 `vvp`；Yosys/GTKWave 可缺失。网页能打开不等于仿真已可用。
- Windows任务使用新克隆内的`.venv`，按2026-10-08复现指南以uv锁定依赖；如副本已存在，另取会话目录，不覆盖旧环境。需要显式工具路径时只在试用终端配置`IVERILOG_PATH`、`VVP_PATH`后重启网页，不动全局PATH。
- Linux/macOS 另发适用命令并记录。发放的是本地副本时不虚构公开仓库 URL；无 `.git` 时记录包版本和哈希。

## T02｜内置离线运行

- 固定一个基准案例，使用“生成测试计划 → 运行测试计划”；不要混成“运行示例测试”。后者可另作扩展并单独记录。
- 当前离线规划器是确定性规则，不是真实 LLM；不要先告诉参与者“正确解释”，观察其能否从页面自行获得这一信息。
- 检查输入与运行 ID 对应，结果来自本轮。参考模型复算、计划显式检查覆盖、实际比对条数、RTL 代码覆盖率不能混写。没有显式期望值时“—”不自动等于失败。
- 组织者预检应确认选定参考实现的执行与检查结果；具体数值留在预检记录，不打印在参与者卡里。

## T03｜已知缺陷

- 复制 `rtl/mod10_counter_bug_wrap9.v` 到试用输入目录，中性命名为 `candidate.v`；接口使用 `examples/mod10_counter_contract.json`，模块名保持 `mod10_counter`。保存原始路径、分发哈希及映射，不发映射给参与者。
- 该变体提前回绕；用本轮离线计划预检是否实际触发差异。没有触发时记录样例/计划覆盖不足，不替换参与者结果为作者预期。
- 没有 RTL 基础者可由组织者只完成上传与接口校验，随后让参与者自行运行、阅读；准备协助与运行中的提示分开记。
- 检查原始 `verdict` 与失败记录。运行完成或 `passed=true` 不能替代设计结论。也可以另用仓库 `tb/tb_mod10_counter.v` 复核，但不可混淆测试路径。

## T04｜自定义输入与接口

- 基础样例复制 `rtl/mod10_counter.v`；接口参考 `examples/mod10_counter_contract.json`。它仍是内置模型支持的模块，不能据此声称验证过任意自定义 RTL。
- 在“接口定义 JSON”文本框把 `clock.period_ns` 从 10 改为 20，再点“用 JSON 刷新表格”，作为反向同步练习；不要改变时钟端口/复位语义来掩盖错误。真实执行周期以已确认合约及生成的 testbench 为准，不用计划的同名字段替代。
- 表格点“从表格生成 JSON”后文本才更新；JSON 修改后点“用 JSON 刷新表格”。修改后必须重新“校验接口”，旧结果应失效。
- 自有 RTL、同名新版本、多模块、`.vh`/include 各作为单独分支记录。没准备多文件夹具就不写成已验证多文件工程。

## T05｜三类对比输入

在新的试用输入目录准备文件。组织者随机或交替安排候选顺序，只给参与者中性编号，映射不公开。

| 输入类型 | 来源或准备方式 | 组织者预检目标 |
|---|---|---|
| 基线 | `rtl/mod10_counter.v` 的原样副本 | 模块与接口可识别，可真实运行 |
| 一致性控制 | 同一基线的另一份逐字副本 | 对比得到 `identical`；只是一致性控制，不是非平凡语义等价改写实验 |
| 行为差异 | `rtl/mod10_counter_bug_wrap9.v` 的原样副本 | 对比得到 `different`，有可定位的输出/检查项差异 |
| 编译失败 | 仅在第三份新副本中保留模块名、端口头部及 `endmodule`，故意破坏模块体中一条赋值的语法 | 能到真实编译环节并产生编译失败诊断；不得输出“两侧一致” |

- 不修改仓库原文件、不发会覆盖原文件的脚本。编译失败副本是故障夹具，不进入正常 RTL 基准；保存其哈希与原始编译日志。
- 先用 CLI `verify-diff` 对每份候选预检；正常对应退出码为一致 `0`、不同 `1`、未取得可比证据 `2`。网页应展示相应结论/诊断。若导入先失败，记录为导入拒绝，不能冒称完成编译失败分支；重新准备夹具后另测。
- 字节相同控制满足本轮最基本一致性检查，**不覆盖结构改写等价性或形式化等价证明**。如将来扩展等价改写，需要另有独立功能依据和文件映射，不用工具自身结论充当真值。
- 每次换候选都要清掉旧对比结果。下载报告必须对应当前候选，不能把前次通过混作后次通过。

## T06｜静态规则与建议

- 固定被审查文件。记录命中的规则、行号、严重度、评分与文件哈希，不用规则总数或分数高低评价参与者操作。
- 规则审查不是仿真。离线“生成修复建议”应披露非 AI 来源，不应改变规则评分；意见与规则发现分开保存。
- 默认不发送代码片段；本卡不需要勾选“同时发送相关代码片段”。若另做在线建议实验，必须另行分配和记录，不能夹入离线试用。

## T07｜状态保留与失效

- 普通导航应保留当前输入、已有结果和设置；改变案例、上传内容、已确认接口或编译选项后，依赖这些输入的计划/结果/导出证据应失效。
- 基础任务不刷新页面、不重启服务。浏览器刷新、重新连接、不同标签页的会话行为另记，不能混成普通切页缺陷。
- 同名文件不同内容是扩展重点；仅看文件名不够，记录内容哈希。自定义 JSON 修改后点到框外，确保编辑已提交，再观察。
- 设置保留只测非敏感字段，不录制真实 API Key；不要求参与者试用在线服务来证明设置保留。

## T08｜档案与证据

- 当前“运行档案”展示最近最多 10 条流水线结果及路径，没有打开、筛选或重跑按钮。示例 testbench 运行不能冒充流水线档案覆盖。
- 核对结果、报告、ZIP 的运行 ID和输入身份；导出后换案例，旧证据不能继续被呈现为新案例结果。
- 清单按当前实际 artifacts 收集文件；不保证包含原始 RTL、所有依赖或可移植重跑命令。交接时另外提供被测 RTL 与版本/哈希；第三方源码按其许可另行处理。
- 重算清单每项的 SHA-256只是完整性核对。独立人员在独立输出目录重跑才是复现证据；ZIP 能解压、目录存在、截图相同都不能代替重跑。

## T09｜CLI 与独立重跑

- 本卡命令已按当前 CLI 参数核对；每次使用新输出目录。显式工具路径需要时以本机实测路径为准，不照搬开发机盘符。
- `plan-run` 使用固定计划文件，不会请求模型。要检查结构化记录和报告，不仅看 shell 返回。
- `verify-diff` 的退出码 `0/1/2` 分别为一致/不同/未取得可比证据；测试范围内一致不证明形式等价。
- 独立复核人员应未参与被审查功能、变体、计划或判据编写，也未准备本轮样例，先拿到输入与命令再执行；记录是否需要作者补文件或指导。内部交叉检查可留档但不冒称外部独立审核。记录双方关系，不公开不必要的个人信息。

## T10｜API 可选分支

- A 预检必须不联网，不因退出 `0` 宣称密钥或模型可用；同时读 `missing`。
- B 回环服务是规则模拟，不是 LLM。端口 11435 被占时换端口须同步两处，不结束其他服务。
- C 不自动分配；只有凭据持有人同意、费用责任和账户侧额度已约定时执行。单案例、单轮、单次请求，失败停止。UI“读取模型列表”也会联网，不能当成纯参数检查。
- 用量与账单分开；未返回 usage 或未拿到账单时留空。不把本次 API 联调视为模型能力实验，不运行策略全批次作为接入测试。

## T11｜窄屏与键盘

- 真机、浏览器响应式模拟、缩放、键盘、读屏器是不同覆盖面，必须标记。纯阅读任务不计为手机完成上传/仿真。
- 检查导航是否可达、正文是否被遮挡、关键按钮是否需要水平整页滚动、焦点是否可见且能离开控件；局部代码/数据表横向滚动与整页溢出分开。
- 屏幕录像要包含一次真实路径和卡点，不仅交静态漂亮截图。组织者预置结果应标明，不能当成参与者自行完成的运行。

## T12｜缺失恢复

- 基础分支是**单次命令的不存在工具路径配置**；配置解析应拒绝它，不能悄悄退回真实安装后仍声称模拟到缺失。原错误日志即证据，不保证产生仿真结果文件。
- 恢复时移除该单次参数、使用新输出目录，正常工具不被删除或改名，全局 PATH 不改。恢复失败保留日志，不让参与者不断修环境。
- 真正的缺安装测试只在新建且可销毁的 VM/容器中做，预先核实没有宿主兜底工具。仅新建 Python venv 不能隔离宿主 Icarus；不要把它写成干净 EDA 环境。
