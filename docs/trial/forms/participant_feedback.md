# 试用者反馈单

请只填写分配给你的任务。完成、卡住、跳过和没记清都可以如实写。无需姓名、电话或其他身份信息；匿名代号由组织者提供，复测时沿用。

| 项目 | 填写 |
| --- | --- |
| 匿名代号 / 本次 session_id | |
| 日期 / 首次试用或复测 | |
| 使用的版本 / 设备 | |
| 是否参与过本项目开发，参与了什么 | |
| 本次分配的任务 ID | |
| 是否同意在参赛材料中匿名引用本次反馈（是 / 否） | |
| 是否同意本次录屏（是 / 否，开始录制前确认） | |

两项同意分别选择。拒绝不会影响试用，可以不录屏；公开引用前可要求去除可识别信息。

为每个分配的任务复制下面一段：

任务状态描述的是你是否完成试用目标，与被测 RTL 的正确性分开。工具报告差异或无法取得结论，也可能已经达到本次观察目标；不要因为 DUT 显示 FAIL 就记成试用失败。操作被页面、工具或环境问题阻断，才记“卡住”。

| 项目 | 填写 |
| --- | --- |
| 任务 ID | |
| 实际状态：完成 / 部分完成 / 卡住 / 跳过 | |
| 大约或计时用时；没记录则写“不知道” | |
| 是否收到提示、解释或有人代操作；具体在哪一步 | |
| 你实际做了什么，页面或工具返回了什么 | |
| 没完成或跳过的原因 | |
| 哪一步容易理解，哪一步难理解（也可写没有明显感受） | |
| 你如何理解结果，它是否回答了本次问题 | |
| 如果只改一处，你会改什么，为什么（可以不选） | |
| 可供核对的截图 / 日志位置（如有） | |

最后还有哪些情况想补充？如果以后遇到类似任务，你会如何处理？哪些条件会影响你的选择？

组织者可将本单转录为 `session_feedback_template.json` 的副本，真人原件保存在被 Git 忽略的 `.iverilog-ai/trial-sessions/`。转录保留原意；事后补填必须标为 `retrospective`，不把“大概”改成计时实测。你没有回答的问题保持空白。
