# 参与者角色与场景覆盖

状态：**试用设计已编写；尚无真人结果，不代表招募或验证已完成。**

本文件供组织者分配任务。标准参与者资料包包含全部任务卡，组织者须标出实际分配项，也可另发个人任务子集；参与者只做分配项。不要把 `tasks/organizer_checks.md`、样例答案或映射一起发出。
安装、使用体验、演示视频与独立复核是不同活动，分别留档；录好演示不等于收到了用户反馈。

## 先了解需求，再分配任务

邀请参与者描述最近一次真实经历，不先演示产品答案。保留“没有相关需求”“通常用别的工具”“不愿接入模型”等回答。

| 角色 | 中性访谈起点 | 本轮主要观察 |
|---|---|---|
| 新手/学生 | 最近一次 RTL 作业怎样确认结果？哪一步花时间最多？ | 是否能启动一个任务、理解结果并找到下一步 |
| RTL 开发者 | 最近一次修改模块后，怎样判断行为有没有变？现有回归输入是什么？ | 上传和接口确认、版本对比、证据能否进入原有工作流 |
| 教学/复核人员 | 如何检查作业或别人交来的验证报告？什么时候需要重新运行？ | 规则与功能结果能否区分、证据能否解释和交接 |
| 安装/CLI 复现者 | 接手开源工具时通常先检查什么？上一次环境问题怎样定位？ | 安装指引、错误诊断、命令与产物是否足够独立复现 |
| 可选 API 用户 | 现在怎样管理服务配置、调用预算和错误？哪些内容不愿外发？ | 预检与真实调用区别、请求预算、脱敏诊断 |
| 手机/窄屏阅读者 | 通常在什么设备上查看结果？主要想查结论、证据还是直接运行？ | 阅读和导航可达性；真实手机与桌面模拟分别记录 |

参与者可以符合多个角色，但一个人仍只算一个人；角色标签不是招募人数。组织者、作者或熟悉实现的人要单列，不能代替完全不了解工具的新手。

## 每人一套小任务，不全跑

建议采用“一个核心任务 + 一个角色任务 + 一个失败/边界情形”。下面是可调整的组合，不是已完成安排。
T07、T08 可接在已经产生结果的任务后做；合并时只计一次运行。安装准备可以在正式可用性计时前完成并单独记录。

| 角色组合 | 核心 | 角色任务 | 失败/边界情形 | 建议活动安排 |
|---|---|---|---|---|
| 新手 | [T02 内置离线运行](tasks/T02_builtin_offline.md) | [T08 导出和交接](tasks/T08_archive_export.md) | [T03 另一实现](tasks/T03_variant_review.md)，组织者仅预置上传与接口 | 25–30 分钟 |
| RTL 开发者 | T02，已有经验者可简短走通 | [T04 自定义接口](tasks/T04_custom_contract.md) | [T05 三份候选对比](tasks/T05_compare_versions.md)；可与 [T07 输入变化](tasks/T07_state_and_input_change.md) 合并 | 35–45 分钟 |
| 教学人员 | T02 | [T06 规则与建议](tasks/T06_static_review.md) | T03，重点解释运行与设计结论；或 T05 的一份候选 | 25–30 分钟 |
| 安装/CLI 复现者 | [T01 安装](tasks/T01_install.md)，预装者记录后跳过 | [T09 命令行复现](tasks/T09_cli_reproduction.md) | [T12 工具路径与恢复](tasks/T12_environment_recovery.md) | 25–40 分钟；下载较慢时另留准备时间 |
| 可选 API 用户 | T02 或已完成的离线 CLI 路径 | [T10 A 预检、可选 B 回环联调](tasks/T10_optional_api.md) | T10 A 的缺配置观察，或 T12；真实 C 另行分配 | 15–25 分钟 |
| 手机/窄屏阅读者 | [T11 阅读既有结果](tasks/T11_narrow_keyboard.md) | T11 导航或键盘分支 | T05 的一个边界候选，文件由组织者预先提供；若只读错误结果，明确标阅读子任务 | 15–25 分钟 |

以上是排期建议，不是实测用时。实际任务计时从开始到完成或停止，包含等待、求助和下载，不含任务间休息；可另记等待时长及原因，不能为展示更快而从任务总耗时中删除。

独立复核另约一次：由**未参与被审查功能、变体、计划或判据编写，也未准备本轮样例的人**接收 T08 交接物，再做 T09 独立重跑分支。优先核对一个正常输入、一个行为差异和一个未取得证据的输入；缺文件或需作者补救本身就是复核结果。内部成员交叉检查可保留，但身份不能写成外部独立审核。更完整的技术审核按 `docs/review/independent_review_guide.md` 另行执行。

第一次可先邀请少量不同背景的人发现问题，修复后再请新的参与者复测。重复同一位熟练者只能说明其复测情况，不能增加“初次使用成功”的人数。安排多少人是招募计划，统计报告以实际参与者和已分配任务为准。

## 需求与任务映射

| 需求或风险 | 主任务 | 最少留存材料 | 不能由此推断 |
|---|---|---|---|
| 能否完成安装和首次运行 | T01、T02 | 环境、耗时、首次错误、求助记录、本次结果 | 在所有机器/平台都能安装 |
| 能否理解仿真结论与不足 | T02、T03、T05 | 参与者原话、结论截图、对应原始结果 | 工具已证明任意 RTL 正确 |
| 自定义接口是否容易确认 | T04 | 上传身份、接口前后版本、校验与卡点 | 任意多文件/多时钟/厂商 IP 均支持 |
| 修改输入后是否误读旧证据 | T07、T05 | 修改前后截图、输入哈希、运行 ID | 刷新、断网、跨会话状态均已验证 |
| 规则建议是否可解释 | T06 | 一条规则依据、参与者意见、评分前后 | 静态高分等于功能正确，或建议等于修复完成 |
| 结果能否导出并被他人复核 | T08、T09 | ZIP、清单、输入来源与哈希、重跑命令/日志 | ZIP 可解压等于完整可复现 |
| 接口配置和费用是否清楚 | T10 | A/B/C分支、脱敏日志、授权与预算记录 | 预检通过等于真实 API 可用；回环服务等于 LLM |
| 窄屏与键盘是否可用 | T11 | 真机/模拟标记、视口、焦点路径、卡点截图 | 桌面缩窄等于所有手机或读屏器已通过 |
| 环境问题是否能安全恢复 | T12 | 单次配置或隔离环境标记、前后命令与日志 | 不存在路径演练等于从空白系统安装完成 |

## 编号、分支与记录口径

- 固定任务 ID 为 T01–T12。同一会话每个任务 ID 只保留一条任务记录；A/B/C、候选编号或自有 RTL 扩展分列在对应客观结果、原因和证据内，不重复 task_id，也不随意创建新的 T 编号。单独安排的复测用新 session_id。
- 反馈状态使用 `completed`（活动完成）、`partial`（只完成部分）、`blocked`（受阻）、`skipped`（明确跳过）。求助后完成仍可为 `completed`，但必须填 `prompt_count` 和 `assistance`；未填写帮助记录不能推断为独立完成。
- 已分配任务没有实际记录属于汇总层的 `missing_record`，不是参与者要填的状态，也不能按完成或跳过处理。未分配的可选分支不进入完成率分母。
- 工具输出 `different`、编译失败或配置错误，不自动等于参与者未完成任务。用户有没有完成指定的观察/交接活动，与工具对设计的结论分开。
- 一人录演示、做试用和做复核时分别标明活动，不把同一条证据重复计算为三位用户支持。组织者演练不得填入真人满意度或独立复核统计。
- 不填写预期数值作为实测值，不给未执行分支填“通过”。不以正面反馈为完成条件；保留“不理解”“不需要”“不同意”等原话。
