# 本地试用材料

## 这套材料是干什么的

竞赛评分里有两条明确要求，靠自己说是不够的：

- 「实现完成度与可验证效果」提到"**用户反馈**"；
- 「开放成果与复用价值」提到"使用说明完整"与复用价值。

所以需要**真人**按文档走一遍，并且把结果如实记下来。这套材料的作用是：让一个
从没见过这个项目的同学，能在 40 分钟内把核心流程跑完，并留下可汇总的记录。

## 目录

| 文件 | 用途 | 谁填 |
|---|---|---|
| `task_card.md` | 试用任务卡：三个任务，逐步操作，含卡住时的排查指引 | 发给试用者 |
| `feedback_template.json` | 反馈表模板：结构化字段，便于汇总 | 复制一份给每个试用者填 |
| `results.md` | 试用结果：真人跑完后的汇总，**未跑之前保持空白** | 汇总人 |

## 使用流程

```powershell
# 1. 把仓库交给试用者（或让他们自己 clone）
# 2. 让试用者按 task_card.md 独立完成，不要在旁边提示
#    —— 需要提示的地方就是文档缺陷，比任何好评都有价值
# 3. 收回填好的 feedback_template.json，汇总进 results.md
# 4. 把试用中发现的问题记进 results.md 的"发现的问题"一节
```

## 如实记录的要求

这套材料本身也要遵守项目的证据口径：

- **不编造反馈。** 没有真人跑过就写"待收集"，不写"用户反馈良好"；
- **失败与卡点优先记录。** "按文档走到第 3 步报错，原因 X"比"整体顺利"有用得多；
- **记录环境。** 操作系统、Python 版本、Icarus 版本、是否装了 Yosys——
  换台机器就复现不了的问题，往往就藏在这里；
- **保留原始记录。** 试用者填的 JSON 原样保存（可去标识），不要润色成"更好看"的版本。

## 试用者需要什么

- 一台能装 Python 与 Icarus Verilog 的电脑（Windows 或 Linux 都行）；
- **不需要** API 密钥：任务 1 与任务 2 全程离线；
- 任务 3 需要一点点 Verilog 基础（能看懂端口与 `always` 块即可）；
- 约 40 分钟。
